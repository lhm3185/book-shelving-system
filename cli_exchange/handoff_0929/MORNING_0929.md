# 1. 오늘 밤 밟은 것

## 1-1. 벽 하나가 남아 있었습니다 — d(reorient) 가 바닥을 뚫는 것
어제 밤 새 레벨에서 3권째가 `403 JOINT_SPEED_EXCEEDED` 로 죽었고, 로그에는 팔 끝이 바닥선보다
**152~329 mm 아래**로 내려앉는 줄이 찍혔습니다. 옛 레벨에서는 한 번도 없던 일입니다.

**옛 레벨에서 같은 코드로 기준선을 떠서 갈랐습니다** (01:29 판):
```
옛 레벨   d 처짐 0 mm · 네 권 완주 · 403 없음
새 레벨   d 처짐 152~184 mm · 3권째에서 403
```
→ 기존 코드의 고질병이 아니라 **새 레벨에서만 생기는 일**임이 확정됐습니다.

## 1-2. 원인 — 팔이 "다른 자세"로 같은 자리에 갑니다
물러나는 순간의 관절값을 두 레벨에서 나란히 놓으니 바로 보였습니다.
```
          j1      j2      j3      j4      j5      j6      j7
옛 3권째 +1.233  -1.226  +1.513  -2.677  -1.290  +2.824  +0.317
새 3권째 +1.155  +1.141  +1.565  -2.784  -2.627  +0.881  -0.252   ← 어깨가 반대로 넘어가 있습니다
```
같은 손끝 위치를 만드는 팔 자세가 여러 개인데(7축이라 무한히 많습니다), 3권째에서만 **먼 자세**가
뽑혔습니다. 그 먼 자세로 가는 도중에 손끝이 내려앉고, 거기서 물러나려니 관절 속도가 98% 까지 올라
403 이 났습니다. **처짐과 403 은 한 원인의 두 증상**이었습니다.

**방아쇠는 레벨의 모양이 아니라 "트레이에서 몇 번째로 뽑히느냐" 였습니다.**
```
옛 레벨 3권째  트레이 y -0.179 (서가에서 먼 자리)  → 스윙 -39.6°
새 레벨 3권째  트레이 y +0.155 (서가에 가까운 자리) → 스윙 -13.3°   ← 출발 자세가 달라집니다
```

## 1-3. 고친 방법 — 앞 권이 성공한 자세를 씨앗으로 씁니다
랩탑과 나눠서 했습니다. 처짐이 문턱(30 mm)을 넘으면:
```
① 앞 권이 꽂기 직전에 도착했던 관절값을 씨앗으로 끝 자세를 다시 푼다  ← 첫 수
② 안 되면 바깥으로 뻗어 손목을 돌리고 들어가는 '되돌림' 으로 바꾼다    ← 둘째 수
③ 안 되면 그 구간을 잘게 나눈다                                      ← 셋째 수
④ 다 안 되면 경고를 남기고 원래대로                                  ← 마지막
```
실제로 판에서 **①이 먹었습니다**: 처짐 152 mm → **0 mm**, 끝 자세도 옛 레벨과 같은 가지(j2 -1.43 · j6 +2.98)로
돌아왔습니다. 숫자 기준(j2 부호 같은 것)을 상수로 박지 않고 **처짐을 재서 고르게** 했으므로, 레벨이나
자세가 바뀌어도 썩지 않습니다.

스위치 이름은 `SIM_D_SAG_MAX_M` (0.03 = 30 mm). **0 이면 꺼집니다.**

  차이가 최대 0.012 rad 로, 같은 판 안에서 나는 흔들림과 같은 크기입니다.

한도를 넘기면 **팀원들 pull 이 막힙니다.**

→ 지금은 **usdc(15.9 MB)·바닥 콜라이더·텍스처 md5 목록만** 저장소에 넣고, **텍스처 216 MB 는 USB** 로 가게
해 뒀습니다. 받는 법은 `simulation/assets/level/Final_Level_Shaded/README.md` 에 적었습니다.
"pull 로 전부 동기화" 라는 지시와 어긋나는 부분이라 말씀드립니다. **올려도 된다고 하시면 한 번에 넣습니다.**
