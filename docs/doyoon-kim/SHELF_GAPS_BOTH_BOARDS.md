# 빈칸은 하나가 아니다 — 내가 틀렸다

2026-09-24 · 김도윤(D) · **도윤님 지적으로 잡힌 것**

## 내가 뭐라고 했나

절차서와 검증 문서에 **"이 판의 빈칸은 하나이고 59.9 mm 다, 그러니 시연은 1권"**
이라고 적었다. **틀렸다.**

도윤님이 "3번째 칸에 빈칸 있고 4번째 칸에 빈칸 있는데?" 라고 하셔서 실측 보고서를
다시 셌다.

## 실측 (`docs/doyoon-kim/measurements/20260923b_shelf_gaps.txt`)

서가 안쪽 x 범위 1.8692 ~ 3.2738. 책 두께 35.2 mm 기준 여유:

```
forthFloor (4번째 칸, 선반판 z 0.4976, 40권)
  1.8692 ~ 1.9152    폭  46.0 mm   여유  +5.4 mm   (왼쪽 옆판과의 틈)
  2.4665 ~ 2.5264    폭  59.9 mm   여유 **+12.4 mm**  ← 지금 쓰는 칸
  3.2310 ~ 3.2738    폭  42.8 mm   여유  +3.8 mm   (오른쪽 옆판과의 틈)

thirdFloor (3번째 칸, 선반판 z 1.0417, 43권)
  1.8692 ~ 1.9108    폭  41.6 mm   여유  +3.2 mm   (왼쪽 옆판과의 틈)
  3.1778 ~ 3.2738    폭 **96.0 mm**  여유 **+30.4 mm**  ← 가장 넉넉하다
```

**쓸 만한 빈칸이 둘이다** — forthFloor 의 59.9 mm 와 thirdFloor 의 96.0 mm.
thirdFloor 쪽이 오히려 여유가 2.5 배 크다.

## 왜 런타임은 "실측 빈칸 1개" 라고 했나 — 두 가지가 겹쳤다

### ① 한 판만 잰다

```python
shelf_gaps=self._shelf_gaps_arm(self.scene.shelf_floor_z)     # ← 판 하나
```

`shelf_floor_z` 는 forthFloor 하나다. **thirdFloor 는 아예 안 잰다.**
스캔은 두 층을 훑는데(`scan_shelf`), 빈칸 측정은 한 층만 한다.

### ② 양 끝 틈을 빠뜨린다

```python
return [[...] for g in _gaps(boxes)]        # shelf_lo / shelf_hi 를 안 넘긴다
```

`gaps()` 는 서가 안쪽 x 범위를 받아야 **옆판과의 틈**을 센다. 안 넘기면 책과 책
사이만 센다. 그래서 forthFloor 의 46.0 / 42.8 두 개가 빠지고 1개만 남았다.

측정 도구(`measure_shelf.py`)는 넘기고, 런타임은 안 넘긴다. **같은 함수를 서로
다르게 부르고 있었다.**

## 이게 왜 위험한가 — 숫자를 놓치는 것으로 끝나지 않는다

빈칸을 1개로 세면 이 규칙이 켜진다:

> **빈칸이 하나뿐이면 거리 제한을 보지 않는다** — 고를 것이 하나면
> "어느 칸을 본 것인지 모르겠다" 가 성립하지 않으니까.

그 규칙은 **정말로 하나일 때** 옳다. 그런데 지금은 **세어 놓고 하나라고 믿는
것**이고, 실제로는 셋이다. 그래서 검출이 173 mm 빗나가도 거리를 안 보고 끌어왔다
(VD11). 결과가 좋았던 것은 **운이 아니라 그 칸이 실제로 맞았기 때문**이지만,
근거가 틀린 채로 맞은 것이다.

그리고 더 나쁜 경우가 있다: 비전이 **thirdFloor 의 빈칸**을 찾아 주면, 맞춤은
forthFloor 의 빈칸 목록과 견준다. x 가 120 mm 안에 들면 **다른 층의 칸으로
끌어당긴다.** 높이(z)는 검출값이 그대로 가므로 **3번째 칸 높이에 4번째 칸 x** 가
된다.

**아직 그런 판을 본 적은 없다.** 비전이 지금까지 forthFloor 쪽만 내놨기 때문으로
보인다 — 확인하지 않았으므로 짐작이다.

## 무엇을 바꿀 것인가 — **아직 안 바꿨다**

도윤님이 **"어제 확인했던 환경이랑 똑같이"** 보고 싶다고 하셨다. 지금 빈칸 측정을
바꾸면 그 확인이 어제와 달라진다. 그래서 **확인 판이 끝난 뒤에** 손댄다.

바꿀 것:

```
1  `_shelf_gaps_arm` 에 서가 안쪽 x 범위를 넘긴다 → 양 끝 틈이 잡힌다
   주의: **바깥 AABB 를 넘기면 안 된다.** 옆판 두께(약 3.3 mm)만큼 틈을 부풀려
   말하게 되고, 여유 +3.8 mm 짜리 칸에서 그건 치명적이다.
   `measure_shelf.py` 가 하듯 메시의 고유 x 값에서 안쪽 범위를 구해야 한다
2  두 판 모두의 빈칸을 잰다. 그리고 빈칸마다 **어느 판인지**를 같이 보낸다
3  맞춤이 **같은 판의 빈칸**끼리만 견주게 한다
4  "빈칸이 하나뿐" 규칙은 **제대로 센 뒤에** 판단한다
```

## 시연 몇 권인가 — 다시 열린 물음

전에 "1권" 이라고 한 근거 중 **"자리가 없다" 는 틀렸다.** thirdFloor 에 96 mm 가
있고 거기는 두 권도 들어간다.

다만 나머지 근거는 그대로다 — 시연 조건 세 판에서 두 권째가 **세 가지 다른
방식**으로 깨졌다 (겹침 · 파지 실패 · 눕힘). 그건 자리 문제가 아니었다.

**그러니 "2권이 되는가" 는 위 1~4 를 고치고 나서 다시 재야 알 수 있다.**
지금 상태로 2권을 약속하면 안 된다.
