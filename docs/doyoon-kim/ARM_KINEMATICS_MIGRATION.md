
## 2. 순서 — 한 번에 하나씩, 판마다 확인

```
① FK 부터 바꾼다 (위험 0)
   `_branch_ok` 의 link_2·3·5 위치를 `ak.fk` 계열로.
   **동작이 안 바뀐다** — 판정에만 쓰이는 값이다. 두 값이 같은지 먼저 찍어 비교한다.

② `ik_joints` 안을 `ak.ik_best` 로 (핵심)
   월드 목표 → 팔 기준으로 바꿔 넣는다 (`scene.to_arm`).
   기존 가드(`_branch_ok`·`_arm_limits`·`_above_deck`)는 **그대로 둔다.**
   스위치 뒤에 두고 기본은 꺼짐 — `SIM_IK_AK=1` 일 때만 새 경로.

③ 한 판씩 견준다
   같은 작업을 옛 경로/새 경로로 한 판씩. 꽂은 자세·겹침·옆여유·구간 시간을 대조.
   **같으면 기본을 켠다. 다르면 왜 다른지 먼저 안다.**

④ 옛 경로를 지운다
   ③이 여러 판 같으면. 그때까지는 **되돌릴 길을 남긴다.**
```

## 2-1. 진행 (2026-09-25 00:40) — ①·② 코드 완료, 판 대조 대기

```
① check_ak_model     e1dc6b0   FK 대조. **처음엔 ee_frame(right_gripper)과 견줘 손끝 오프셋
                                ~10 cm 가 "모델 불일치" 로 읽힐 뻔했다** — ak 는 손(panda_hand)
                                을 모형화한다. hand_link 와 견주도록 고쳤다.
② _solve_ik          (이 커밋)  원시 Lula IK 호출이 이 한 곳으로 들어갔다. SIM_IK_AK 로 고른다.
```

### `SIM_IK_AK` — 세 값

```
0         Lula 만. 기본. 지금까지의 동작 (한 줄도 안 바뀐다)
compare   Lula 로 풀어 **그대로 쓰고**, 같은 목표를 ak 로도 풀어 차이만 센다 → 위험 0
          로그: [IK대조] N번: 둘다 · Lula만 · ak만 · 둘다못 · 해 차이 최대 rad · 손끝 오차 mm
1         ak 로 푼다. ak 가 못 푸는 프레임(손·손끝 밖)이면 그 호출만 Lula 로
```

**순서: `compare` 로 두 권 한 판 → `Lula만` 이 0 이고 손끝 오차가 mm 대면 `1` 로 아래 판
5/5 → 두 권 3판.** `Lula만` 이 0 이 아니면 ak 가 못 푸는 목표가 있는 것이고, 그게 어느
구간인지 알기 전에는 `1` 로 안 간다.

### 기준을 같게 맞춘 것 — compare 의 차이가 풀이기 차이만 되게

```
허용 오차       Lula 호출과 같은 0.004 m · 0.05 rad
한계 여유 필터   ak.ik(min_margin=0)  ← ak 기본 0.10 을 끈다
```

한계 검사는 `ik_joints` 의 가드 `_arm_limits` 가 **두 풀이기에 똑같이** 건다. ak 의 0.10 rad
필터를 켜 두면 Lula 가 통과시키던 한계 근처 해를 ak 만 버려서, compare 의 `Lula만` 이
풀이기 차이가 아니라 기준 차이로 부풀 것이다. 그 필터는 ③ 뒤에 **따로** 켤지 정한다 —
오프라인 표에서 위 판 pre_ins 여유가 0.116 이라 0.10 은 거의 벼랑이다.

### 프레임 — 손으로 적지 않는다

ak 목표는 팔 기준·손(panda_hand) 기준이다. 월드 목표는 `to_arm`, 손끝(ee_frame) 목표는
**기동 때 Lula FK 두 프레임에서 한 번 잰** 손→손끝 고정 변환(`_ak_tool`, 로그 `[IK] 손→
right_gripper 고정 변환`)으로 손 자세로 바꿔 넣는다 (`ak.hand_pose_for_tool`, 시험
`test_ak_tool_frame.py`).

### 알고 가는 것 — ak 풀이기가 위 판 띠에서 흔들린다

오프라인 표(00:10)에서 z 0.86·0.84 는 풀리는데 그 사이 0.8837 이 안 풀렸다. 댐핑 최소자승이
그 띠에서 국소해에 갇히는 것으로 보인다. `ik_joints` 의 씨앗 흔들기가 그걸 얼마나 덮는지가
compare 의 `Lula만` 수에 나온다. **위 판이 지금보다 나빠질 수 있다** — 그래서 아래 판 5/5
없이 기본을 안 바꾼다.

## 3. 미리 아는 함정 셋

### 3.1 `arm_kinematics` 는 **Franka 전용**이다

```python
# 로봇 상수 (Franka Panda, 수정 DH)
_DH = [...]
```

M0609 로 바꾸면 이 표가 없다. **시연은 Franka 이므로 지금은 문제가 아니지만,
문서에 한 줄 적어야 한다** — 로봇을 바꾸면 ②가 통째로 멈춘다.

### 3.2 좌표계가 다르다

```
Lula   월드 기준 (`set_robot_base_pose` 로 베이스를 알려 준다)
ak     **팔 기준** (arm_base_link)
```

`book_scene` 은 `yaw_to_world` 로 월드에 바꿔 놓고 IK 를 푼다. `ak` 를 쓰면 그
변환이 **사라진다** — 오늘 좌표 사고의 절반이 월드/팔 기준을 섞은 것이었으니
이건 이득이다. 다만 **바꾸는 그 판에서는 위험**하다. 그래서 ②를 스위치 뒤에 둔다.

### 3.3 `ik_seed_limit` 가드는 남겨야 한다

`ik_joints` 는 "씨앗에서 너무 먼 해를 버린다" 를 한다. `ak.ik_best(prefer=q)` 도
비슷한 일을 하지만 **같지 않다.** 둘 다 둔 채로 시작하고, ③에서 같은 결과가
나오는지 본 뒤에 정리한다.
