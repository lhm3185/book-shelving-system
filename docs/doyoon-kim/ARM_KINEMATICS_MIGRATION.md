## 0. 왜 하나 — 이유가 이미 코드에 적혀 있다

`book_scene.ik_joints` 주석:

> Lula 가 **거짓 한계**(j6 3.75, 실제 3.0)로 도달 불가 해를 돌려주고 팔이 한계에
> 붙은 채 404 로 죽는다 (2026-09-23).

그래서 스캔은 9/23 에 이미 `arm_kinematics` 로 옮겼고(`plan_board_sweep`),
그 뒤로 스캔에서 그 문제가 안 났다. **나머지도 같은 이유로 옮긴다.**

`arm_kinematics` 가 Lula 와 다른 점:

```
한계 여유를 직접 잰다        limit_margin() — 계획 단계에서 거를 수 있다
여러 씨앗에서 풀고 고른다     ik_best(seeds_around(q), prefer=q) — 가지가 안 튄다
팔 기준에서 푼다             월드 변환이 사라진다 (오늘 좌표 사고의 절반이 그것이었다)
Isaac 없이 돈다              **GPU 없이 시험할 수 있다** ← 오늘 이게 가장 컸다
```

## 1. 범위 — 생각보다 좁다

`book_scene.py` 의 Lula 호출 13곳 중 **IK 는 한 곳뿐**이고 나머지는 전부 FK 다.

```
1663  compute_inverse_kinematics      ← **이 한 줄이 전부다** (`ik_joints` 안)
 890  compute_forward_kinematics      링크 이름 확인 (기동 시 1회)
 901  compute_end_effector_pose       손끝 자세 읽기
1029  compute_forward_kinematics      홈 손끝 (기동 시 1회)
1441~3 link_2·3·5 위치               팔꿈치↑ 가지 판정
1489  이름별 FK                        진단 덤프
1854·1895·1971  ee FK                 스윙 경로 검사
 872·1261  set_robot_base_pose        베이스 자세 갱신
```

**코드가 이미 그 한 곳으로 몰아 놨다:**

> 원시 Lula 호출은 저장소 안에서 **여기 한 곳뿐이어야 한다.** 가드를 우회하는
> 경로가 생기면 스캔이 겪은 일이 그대로 재발한다.
> 회귀 점검: `grep -rc 'self[.]lula[.]compute_inverse_kinematics(' controllers/` → **1**

## 2. 순서 — 한 번에 하나씩, 판마다 확인

```
① FK 부터 바꾼다 (위험 0)
   `_branch_ok` 의 link_2·3·5 위치를 `ak.fk` 계열로.
   **동작이 안 바뀐다** — 판정에만 쓰이는 값이다. 두 값이 같은지 먼저 찍어 비교한다.

② `ik_joints` 안을 `ak.ik_best` 로 (핵심)
   월드 목표 → 팔 기준으로 바꿔 넣는다 (`scene.to_arm`).
   기존 가드(`_branch_ok`·`_arm_limits`·`_above_deck`)는 **그대로 둔다.**
   스위치 뒤에 두고 기본은 꺼짐 — `SIM_IK_AK=1` 일 때만 새 경로.

③ 한 판씩 견준다
   같은 작업을 옛 경로/새 경로로 한 판씩. 꽂은 자세·겹침·옆여유·구간 시간을 대조.
   **같으면 기본을 켠다. 다르면 왜 다른지 먼저 안다.**

④ 옛 경로를 지운다
   ③이 여러 판 같으면. 그때까지는 **되돌릴 길을 남긴다.**
```

## 3. 미리 아는 함정 셋

### 3.1 `arm_kinematics` 는 **Franka 전용**이다

```python
# 로봇 상수 (Franka Panda, 수정 DH)
_DH = [...]
```

M0609 로 바꾸면 이 표가 없다. **시연은 Franka 이므로 지금은 문제가 아니지만,
문서에 한 줄 적어야 한다** — 로봇을 바꾸면 ②가 통째로 멈춘다.

### 3.2 좌표계가 다르다

```
Lula   월드 기준 (`set_robot_base_pose` 로 베이스를 알려 준다)
ak     **팔 기준** (arm_base_link)
```

`book_scene` 은 `yaw_to_world` 로 월드에 바꿔 놓고 IK 를 푼다. `ak` 를 쓰면 그
변환이 **사라진다** — 오늘 좌표 사고의 절반이 월드/팔 기준을 섞은 것이었으니
이건 이득이다. 다만 **바꾸는 그 판에서는 위험**하다. 그래서 ②를 스위치 뒤에 둔다.

### 3.3 `ik_seed_limit` 가드는 남겨야 한다

`ik_joints` 는 "씨앗에서 너무 먼 해를 버린다" 를 한다. `ak.ik_best(prefer=q)` 도
비슷한 일을 하지만 **같지 않다.** 둘 다 둔 채로 시작하고, ③에서 같은 결과가
나오는지 본 뒤에 정리한다.
