## 단계 −1 — **재현 불가** (사유 기록)

지시: "지금 코드(필터 여유 2 cm) 그대로 `down` 점프 때 j3 부호를 본다."

**그 점프가 코드에서 사라졌다.** 1.96 rad 점프는 `_above_deck` 가 **링크 원점 높이**로
해를 버리던 판(2026-09-21 오후 초)에서만 났다. 회신을 받기 전에 이미 **기술서 충돌 구**
기반으로 바꿔 두었고, 그 뒤로는 `down` 이 점프하지 않는다 (계획이 그냥 통과).

**간접 확인으로 본다** — 필터 구현을 바꾸자 점프가 사라진 것은 "필터가 해를 버려
가지가 갈렸다"는 설명과 일치한다. 다만 **j3 부호로 직접 본 것은 아니다.**

## 병행 트랙 — M406

### T2 (조인트 대상 prim) — **H2 기각**

| 확인 | 결과 |
| --- | --- |
| 책 에셋 자체의 물리 API | **없음** (usdc 토큰 검사: `PhysicsRigidBodyAPI` 등 0건) |
| `RigidBodyAPI` 를 붙이는 곳 | `book_scene.py:293` — `/World/bs_books/book_i` |
| 조인트 `body1` | **같은 prim** (`attach()`) |

→ **조인트는 강체를 제대로 잡고 있다.** 강체가 이중이라는 예전 설명도 틀렸다
(그래서 §2-8 의 키네마틱 실패 원인은 **다시 미상**으로 돌려놓았다).

### H1 — 지금 가장 그럴듯한 설명 (아직 시험 안 함)

`attach()` 는 고정 조인트를 만들기 직전에 **책을 세운 자세로 USD 에 써 넣는다**:

```python
if book in self.upright_q:
    p_now = SingleXFormPrim(book).get_world_pose()[0]
    SingleXFormPrim(book).set_world_pose(np.asarray(p_now, float), self.upright_q[book])
hp, hq = SingleXFormPrim(HAND_LINK).get_world_pose()
bp, bq = SingleXFormPrim(book).get_world_pose()      # ← 방금 써 넣은 '세운' 자세를 읽는다
```

물리가 도는 중에 동적 강체의 USD 변환을 써도 **PhysX 는 자기 상태를 그대로 쓴다.**
그러면 앵커는 "세운 책" 기준으로 만들어지는데 실제 책은 **기울어진 채**다.
조인트는 그 차이를 메우려 책을 **세운 자세 쪽으로 계속 끌어당긴다** —
들어 올리는 0.7초 동안 매끄럽게 자라다 평형에서 멈추고, z ≈ 0, 방향 일정.
**M406 의 모양과 정확히 맞는다.**

**판별**: 조인트 생성 1 스텝 뒤, 물리 뷰에서 읽은 책 자세와 우리가 쓴 자세의 차이를 찍는다.
0 이 아니면 확정. **규칙 4 에 따라 경로 A 가 끝나기 전에는 고치지 않는다.**
