# 카메라 토픽 이름이 겹칩니다 — 결정 필요 (로봇팔 → 팀 전체)

| 항목 | 값 |
| --- | --- |
| 작성 | 2026-09-19, D 김도윤 |
| 발견 경위 | AMR 담당이 다른 GPU PC 에서 **rqt 로 카메라를 받는 시험** 중, 화면에 **우리 로봇팔 픽앤플레이스 영상**이 떴다 |
| 성격 | 버그가 아니라 **이름 충돌**. 지금은 서로 비켜 가며 쓰고 있지만 **시연 당일에도 그대로 터진다** |

## 1. 무슨 일이 일어났나

```
같은 ROS_DOMAIN_ID = 130
  ├─ 로봇팔 Isaac  →  /rgb  /depth  /camera_info   (손목 RealSense)
  └─ AMR 카메라    →  /rgb  ...                     (같은 이름)
```

ROS 2 에서 **같은 이름의 토픽은 같은 토픽**이다. 구독자는 어느 쪽이 보낸 것인지 구분하지 못하고,
둘 다 발행 중이면 **프레임이 섞여서** 들어온다.

오늘은 우리가 먼저 띄워 두었기 때문에 AMR 담당 rqt 에 우리 영상이 잡혔다. 반대도 똑같이 일어난다.

## 2. 왜 지금 정해야 하나

| 시점 | 증상 |
| --- | --- |
| 지금 (각자 시험) | "내 카메라가 아닌 게 보인다" — 눈에 띄어서 알아챌 수 있다 |
| **통합 시연** | **비전이 AMR 카메라 프레임으로 책을 찾으려 한다** — 검출이 안 되는 이유를 못 찾는다 |

두 번째가 위험하다. 증상이 "비전이 책을 못 찾는다" 로만 보여서, 카메라가 바뀐 줄 모른 채
모델이나 임계값을 의심하게 된다. **오늘 비전에서 이미 겪은 것과 같은 종류의 함정**이다.

## 3. 선택지

| 방법 | 내용 | 평가 |
| --- | --- | --- |
| **① 네임스페이스 분리** | 로봇팔 `/arm/rgb`, AMR `/amr/rgb` | **권장.** 근본 해결이고 시연에서도 안전 |
| ② 도메인 분리 | 시험 중에만 서로 다른 `ROS_DOMAIN_ID` | 임시방편. 통합 시연에서는 다시 합쳐야 해서 문제가 그대로 돌아온다 |
| ③ 시간 분리 | 겹치는 시간에 한쪽만 실행 | 지금 방식. 매번 조율해야 하고 시연 당일에 쓸 수 없다 |

### ① 을 고르면 바꿔야 하는 곳

**우리 쪽은 이미 준비해 두었다.** 실행 옵션 한 줄로 바뀐다 (기본값은 지금과 같아서, 정하기 전까지 아무 영향 없다).

```bash
./scripts/run_isaac_sim.sh --headless --camera-ns /arm   # → /arm/rgb /arm/depth /arm/camera_info
```

| 담당 | 바꿀 곳 |
| --- | --- |
| 로봇팔 (우리) | **완료** — `--camera-ns /arm` 만 붙이면 됨 |
| 비전 | `perception.yaml` 의 `rgb_topic` · `depth_topic` · `camera_info_topic` |
| AMR | 카메라 발행 토픽 이름 |
| FSM | 없음 (카메라 토픽을 직접 안 씀) |

비전 쪽은 **이미 파라미터로 빠져 있어** 코드 수정 없이 yaml 한 곳만 고치면 된다.

## 4. 같이 볼 것 — `/tf` 와 `/clock` 도 공용이다

카메라만의 문제가 아니다.

| 토픽 | 지금 | 겹치면 |
| --- | --- | --- |
| `/tf` | 양쪽이 각자 발행 | 프레임 이름이 같으면 **TF 트리에 고리**가 생긴다 (9/17 에 이미 한 번 겪음) |
| `/clock` | Isaac 이 발행 | **둘 다 발행하면 시뮬 시각이 튄다** — `use_sim_time` 쓰는 노드가 전부 영향받는다 |

`/clock` 은 특히 위험하다. **시뮬레이터는 한 판에 하나만 `/clock` 을 발행해야 한다.**
통합 시연에서 Isaac 을 두 대 띄우는 구성이라면 미리 정해야 한다.

## 5. 제안

1. **1차 시연 구성을 먼저 확정**한다 — Isaac 을 한 대만 쓰는가, 두 대인가
2. 한 대면: 카메라 네임스페이스만 나누면 충분하다 (`/arm`, `/amr`)
3. 두 대면: `/clock` 을 어느 쪽이 낼지, TF 프레임 이름을 어떻게 나눌지까지 정해야 한다
4. 정해지면 **우리 쪽은 옵션 한 줄**이라 바로 반영 가능하다

**그 전까지는 시간 분리(③)로 비켜 간다.** 우리가 돌릴 때 미리 알리겠다.
