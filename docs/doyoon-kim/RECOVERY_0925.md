
**여기서 코드를 고치지 않는다.** 안 되면 안 되는 대로 기록한다 — "어제 되던 것"
이라는 전제 자체가 틀렸다는 뜻이고, 그것도 알아야 할 사실이다.

## 3. 자세를 나눈다 — `q_scan` / `q_pick`  [1시간]

원인은 홈 자세 하나가 **두 가지 뜻을 겸한 것**이다.

```
yaml 홈      파지 여유 0.128 (작다)  ·  아래 판 스윕 5/5 (0.166)   ← 스캔에 좋다
SIM_HOME_Q   파지 여유 0.707 (크다)  ·  아래 판 스윕 3/5 (0.100)   ← 파지에 좋다
```

**하나를 고를 일이 아니다. 나눈다.**

```
q_scan   스캔 진입 자세 = yaml 홈 계열
q_pick   파지 진입 자세 = SIM_HOME_Q 계열
사이클:  … → moveJ(q_scan) → 스캔 → moveJ(q_pick) → 파지 → 삽입 → …
```

전이는 `moveJ` 한 번. 몇 초 더 걸리지만 **두 구간이 각자 최적 자세에서 돈다.**

**2번이 끝나기 전에는 쓰지 않는다.** 이것도 "확인 전에 고치기" 가 된다.

## 5. 이날부터 **모든 판이 자기 구성을 찍는다**

오늘 사고 넷 중 셋은 이것만 있었어도 첫 판에서 드러났다.

```
목표:      (한 문장 — 이 판으로 무엇을 확인하는가)
기준선:    (비교 대상 판 ID)
git:       (해시)      level: (md5)
q_home 실제값 · 환경변수 전체 · 프리셋 이름
```

**목표 문장과 기준선이 없으면 판을 돌리지 않는다.**

왜 이게 표류를 잡나: 동작을 바꾸면 **비교 대상이 더 이상 유효하지 않다.**
그러면 `기준선:` 을 고쳐야 하고, 고치는 것은 **사람이 내리는 명시적 결정**이 된다.
오늘은 그 결정이 아무 데서도 일어나지 않았다 — `scan_shelf` 로 갈아탄 뒤에도
앞 판들과 계속 비교하고 있었다.

> **표류는 도구로 안 잡히고 문장으로 잡힌다.**
> 오늘 도구를 7,584줄 붙였고, 원인을 찾은 것은 로그 한 줄이었다.
