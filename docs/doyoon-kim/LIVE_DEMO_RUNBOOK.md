## 0. 지금 숫자 — 무엇이 걸릴 확률인가

```
배치 품질     맞춤 적용 16판 / 16 합격 · 배치 실패 0
              → **이쪽은 걱정하지 않는다.** 여기서 멈춘 적이 없다

완주          멈춘 자리는 전부 배치 **바깥**이다
```

**"고쳤다" 와 "안 난다" 는 다르다.** 위 둘은 고친 뒤로 재현되지 않았는데, 그건
확인이 아니라 **안 나온 것**이다. 절차는 그 둘이 여전히 난다고 보고 짠다.

## 1. 무대에 서기 전 — 이 순서를 지킨다

시간이 드는 것을 전부 앞으로 뺀다. **무대 위에서 하는 일이 적을수록 좋다.**

### 1.1 T−30분: Isaac 을 띄워 둔다

```bash
bash cli_exchange/scripts/run_vision.sh REHEARSAL "SIM_DETECT_SLOT=1"
```

**이것이 가장 값싼 이득이다.** 완주 실패의 가장 큰 조각(6.4%)이 기동인데,
기동은 무대 전에 끝내면 그만이다. 재시도 감싸개가 붙어 있어 한 번 실패해도
다시 뜬다 — 다만 **무대 위에서는 그 20초를 못 기다린다.**

> **미확인**: "띄워 놓고 얼마나 기다려도 되는가" 를 안 쟀다. 30분·1시간 뒤 첫 판이
> 멀쩡한지 확인해야 한다. 확인 전에는 **T−10분 재기동**을 권한다.

### 1.2 초록불의 정의 — 이 셋이 다 맞아야 무대에 선다

```
① sim.log 에 `준비 완료` 가 있다
   grep -c '준비 완료' <판>/sim.log        → 1 이상

② 예행 한 판이 합격이다
   python3 simulation/isaac/tools/judge_run.py <판>
   → 합격 · 겹침 0.0 · 옆여유가 +5 mm 넘는다

③ 레벨과 코드가 예행 때와 같다
   판정 출력의 `레벨 <md5> · 코드 <sha>` 를 적어 둔다
```

**③ 을 적어 두는 이유**: 무대 판이 이상하면 제일 먼저 볼 것이 "예행과 같은
것을 돌리고 있나" 다. 기억에 의존하면 그 자리에서 확인이 안 된다.

### 1.3 예행에서 합격이 안 나오면 — 무대에 서지 않는다

한 판 더 돌린다. 두 판 연속 불합격이면 **구성이 바뀐 것**이다. 순서:

```
1) 옆여유를 본다        5 mm 안쪽이면 서가 책 배치가 예행과 다르다
2) 레벨 md5 를 본다      다르면 레벨이 바뀌었다 — 빈칸 위치가 달라진다
3) 코드 sha 를 본다      다르면 누가 push 한 것을 받았다
```

## 2. 무대 위 — 멈추면 무엇을 하는가

**판단의 기준은 하나다: 10초 안에 다시 움직이기 시작하는가.**

| 증상 | 어디서 보나 | 원인 | 그 자리에서 |
|---|---|---|---|
| 팔이 **책을 든 채** 멈춘다 | `man.log` 가 안 늘어난다 | 노드 사망 | **노드만 다시 띄운다** (아래 2.1) |
| 요청마다 **곧바로 거절**된다 | `작업 … 실행 중` 이 반복 | 노드가 엎어져 걸림 | 같다 — 2.1. **기다려도 안 풀린다** |
| 팔이 멈췄는데 로그는 돈다 | `ROTATING_BASE` 에서 멎음 | 회전 | 30초 기다린다 — 이제 `SIM_CANCELLED` 로 끊긴다 |
| `410` 이 뜬다 | 결과 메시지 | **거절이다** | 재시도. 같은 결과면 칸이 바뀐 것 |
| `409` 가 뜬다 | 결과 메시지 | 꽂혔는데 확인 실패 | 그 칸을 점유로 기록하지 않는다 |
| Isaac 창이 사라진다 | — | 기동/런타임 크래시 | **판을 접는다** (2.2) |

> **노드가 죽으면 로봇은 책을 든 채로 멈춘다.** 피드백을 보내다 터진 예외가
> 실행 스레드를 끝내는데, 그리퍼는 안 풀리기 때문이다. 무대에서 이 그림이 나온다 —
> "팔이 책을 들고 정지". 한 경로는 고쳤지만 확인되지 않았다.

### 2.1 노드만 다시 띄우기 — 유일하게 무대 위에서 할 만한 복구

**"유일한" 이 과장이 아니다. 실측으로 확인됐다.** 2026-09-24 LIVE1 에서 조작 노드가
첫 목표에서 죽은 뒤 6 사이클 내내 이랬다:

```
시뮬        6 사이클 내내 멀쩡     ← 무대 전에 띄워 두는 것이 안전하다는 근거
주행        왕복 6회, 12번 다 성공  ← 이쪽은 걱정이 아니다
조작 노드   **한 번 엎어지면 못 일어난다**
            죽은 목표가 '실행 중' 으로 걸려 그 뒤 모든 요청을 거절한다
            ("DetectTargetSlot 목표 거절: 작업 scan 실행 중")
```

**노드는 스스로 회복하지 않는다.** 25초마다 거절만 하면서 끝까지 살아 있었다 —
프로세스는 죽지 않으니 "죽었다" 고 보이지도 않는다. 증상은 **거절**이다.

`manipulation_node` 는 Isaac 과 별개 프로세스다. **Isaac 을 살려 둔 채 노드만
다시 띄울 수 있고, 5초쯤 걸린다.**

```bash
kill -INT <man_pid>          # PID 로만 죽인다. 패턴으로 훑지 않는다
ros2 run shelving_manipulation manipulation_node \
  --ros-args --params-file ros2_ws/src/shelving_manipulation/config/manipulation.yaml
```

**손에 책이 들려 있으면 그대로 있다.** 노드는 상태를 잃지만 그리퍼는 안 풀린다
(취소 경로가 `HOLD_GRIP` 이다). 다시 띄운 뒤 `PlaceBook` 을 새로 보내면 된다.

> `pgrep -f` 로 찾지 않는다. 그 패턴이 자기 자신과 부모 셸까지 잡은 적이 있다.
> **PID 를 미리 적어 둔다** — `run_vision.sh` 가 `<판>/sim.pid` 에 남긴다.

### 2.2 판을 접어야 할 때

Isaac 이 죽으면 22초 + 장면 준비가 필요하다. **무대에서 그건 복구가 아니다.**
미리 정해 둘 것:

```
누가 말하는가        멈춘 것을 설명할 사람 (도윤님 / FSM 담당자)
무엇을 말하는가      아래 3절
다음에 무엇을 보여주나  예행 녹화본이 있으면 그것. 없으면 다른 부분으로 넘어간다
```

**이 셋을 미리 안 정해 두면 무대 위에서 정하게 된다.**

## 3. 멈췄을 때 할 말 — 이건 변명이 아니라 사실이다

우리 시스템에는 **일부러 멈추는 자리**가 있다. 그걸 구분해서 말하면 멈춘 것이
오히려 설계의 증거가 된다.

```
410 이 떴다        "빈칸을 찾았는데 확신이 없어서 넣지 않았습니다.
                   억지로 넣으면 옆 책을 밀어냅니다"
                   → **사실이다.** 문턱을 낮춰 통과시키지 않는 것이 우리 원칙이다

409 가 떴다        "넣긴 했는데 제대로 들어갔는지 확인이 안 돼서
                   재고에 반영하지 않았습니다"
                   → **사실이다.** 확인된 것만 기록한다

노드가 죽었다      "소프트웨어 하나가 죽었습니다. 다시 띄웁니다" — 5초
Isaac 이 죽었다    시뮬레이터 자체 문제다. 우리 코드 밖이라는 근거가 있다
                   (breakpad 스택이 GPU 플러그인을 가리킨다)
```

**410·409 를 "실패" 로 말하지 않는다.** 그건 검사가 일한 것이다. 다만
**되는 것처럼 꾸미지도 않는다** — 안 들어간 건 안 들어간 것이다.

## 4.0 시연은 **두 권**이다 — 2026-09-25 새벽에 됐다

어제 이 절은 "두 권째는 자리가 없다" 였다. 어제 레벨 얘기다. 도윤님이 레벨을 고쳐 판이 둘이
됐고(`reach_check.py`: 판 0.4976 빈칸 2개·최대 60 mm, 판 1.0417 빈칸 2개·최대 56 mm), 그
레벨에서 **두 권을 꽂고 홈으로 돌아왔다** (01:14 판):

```
1권 아래 판   중심 -0.0 mm · +0.16° · 겹침 없음
2권 위  판    중심 -1.5 mm · +0.43° · 겹침 없음
홈 복귀       (+4.986, -5.607) yaw +90.00°  = 출발 자리
한 판 시간    두 권 ≈ 10~11 분 (한 권 5분 10초 ~ 5분 43초)
```

**위 판이 위험하다.** 팔 작업 공간 가장자리다(꽂는 자세 여유 0.224, 아래 판 0.650). 두 권째가
막히는 방식은 오늘 밤 셋이었고 셋 다 고쳤다(VERIFICATION_AND_LIMITS 5.3.1). 그 뒤 **기본값만으로
4/4** (02:05, 1권 +1.3~+2.4 mm · 2권 −1.5~−0.5 mm · 복귀 네 판 동일). 네 판이지 열 판이 아니다 —
**예행 당일 두 권 판이 다시 되는 것을 보고 나서** 무대에서 두 권을 약속한다. 안 되면 한 권으로
접는다 — 한 권은 열일곱 판째 −3.3 ~ +2.4 mm 다.

> 레벨을 다시 고치면 **`reach_check.py <레벨>` 부터** 돌린다. 판마다 꽂는 자세·운반 경유점·
> pre_ins 가 풀리는지를 시뮬 없이 낸다. 위 판이 `경유 DOWN ✗ · HORIZ ○ → 자세 사다리 2번째`
> 로 나오면 오늘 밤과 같은 상태다.

## 4.1 여러 권을 연속으로 꽂을 때 — 반드시 **매 판 다시 스캔한다**

빈칸은 스캔할 때 잰다. **책을 한 권 꽂으면 그 빈칸이 없어진다.** 다시 안 재고 그
값을 쓰면 방금 채운 자리에 또 꽂는다.

```
매 사이클   DetectTargetSlot → PlaceBook      ← 이 순서를 지킨다
틀림        DetectTargetSlot 한 번 → PlaceBook 여러 번
```

노드가 이제 **스스로 거절한다** — 마지막 실측 이후에 배치가 있었으면 `410` 을 내고
사유에 "다시 스캔해야 한다" 가 들어간다. 그래도 무대에서 그 410 을 보는 것보다
순서를 지키는 편이 낫다.

> 이것은 **한 판에 사이클 하나만 돌면 절대 안 보인다.** 9/24 까지 잰 것이 전부
> 그 조건이었다 — 판마다 시뮬과 노드를 새로 띄웠다. **시연 조건은 다르다.**

## 5. 시연 전까지 남은 일 (우선순위)

```
1  **시연 조건으로 잰다**       시뮬·노드를 한 번 띄우고 사이클 여러 번.
                               지금까지 잰 것은 전부 "판마다 새로 띄우고 1번" 이라
                               **시연 조건은 한 번도 안 쟀다** (데스크탑 지적)
2  띄워 둔 뒤 첫 판 확인        1.1 의 미확인 항목. 30분·1시간을 1판씩
3  예행 녹화본 확보             2.2 의 대비책. 영상은 도윤님·FSM 담당자 영역
4  PID·명령을 손 닿는 곳에      2.1 을 무대에서 찾아 헤매지 않게
5  노드 사망 재현 시도          1 에서 자연히 나올 수 있다. 안 나면 "미확인" 으로 적는다
```

**1 이 다른 넷을 합친 것보다 중요하다.** 사이클이 사이클을 망치는지는 그 조건에서만
보이고, 무대는 그 조건이다. 4.1 의 함정도 거기서만 드러난다.

3 은 확률을 못 낮추지만 **멈췄을 때의 손실을 줄인다.**

## 6. 이 문서가 보증하지 않는 것

- **"안 멈춘다" 를 보증하지 않는다.** 16판에 사고 1회를 봤고, 표본이 그것뿐이다.
- 고친 두 가지(노드 사망·회전)는 **고친 뒤 재현되지 않았을 뿐** 확인되지 않았다.
- 여기 적힌 복구 시간(5초·30초)은 **재 본 값이 아니라 설계상의 값**이다.
  예행에서 한 번 해 보고 실제 시간을 적어야 한다.
- **완주율 숫자(16판 중 사고 1회)는 시연 조건의 값이 아니다.** 판마다 시뮬과
  노드를 새로 띄운 조건에서 나온 값이다. 시연 조건(한 번 띄우고 여러 사이클)의
  숫자는 아직 없다 — 그게 5절 1번이다.
