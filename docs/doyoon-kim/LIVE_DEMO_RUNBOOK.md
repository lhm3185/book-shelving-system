# 생중계 시연 절차서 — 로봇팔

김도윤(D) · 2026-09-24 작성 · **9/30 최종 발표는 실시간 시연이다**

녹화가 아니다. **한 판이 전부다.** 그래서 이 문서는 "어떻게 하면 잘 되는가" 가
아니라 **"멈추면 몇 초 안에 무엇을 하는가"** 를 적는다.

---

## 0. 지금 숫자 — 무엇이 걸릴 확률인가

```
배치 품질     맞춤 적용 16판 / 16 합격 · 배치 실패 0
              → **이쪽은 걱정하지 않는다.** 여기서 멈춘 적이 없다

완주          멈춘 자리는 전부 배치 **바깥**이다
              Isaac 기동 실패   110판 중 6.4%   ← 무대 밖으로 뺄 수 있다 (2절)
              노드 사망          16판 중 1회    ← 한 경로를 고쳤다. 미확인
              회전 무응답        1회            ← 세 겹을 고쳤다. 미확인
```

**"고쳤다" 와 "안 난다" 는 다르다.** 위 둘은 고친 뒤로 재현되지 않았는데, 그건
확인이 아니라 **안 나온 것**이다. 절차는 그 둘이 여전히 난다고 보고 짠다.

---

## 1. 무대에 서기 전 — 이 순서를 지킨다

시간이 드는 것을 전부 앞으로 뺀다. **무대 위에서 하는 일이 적을수록 좋다.**

### 1.1 T−30분: Isaac 을 띄워 둔다

```bash
bash cli_exchange/scripts/run_vision.sh REHEARSAL "SIM_DETECT_SLOT=1"
```

**이것이 가장 값싼 이득이다.** 완주 실패의 가장 큰 조각(6.4%)이 기동인데,
기동은 무대 전에 끝내면 그만이다. 재시도 감싸개가 붙어 있어 한 번 실패해도
다시 뜬다 — 다만 **무대 위에서는 그 20초를 못 기다린다.**

> **미확인**: "띄워 놓고 얼마나 기다려도 되는가" 를 안 쟀다. 30분·1시간 뒤 첫 판이
> 멀쩡한지 확인해야 한다. 확인 전에는 **T−10분 재기동**을 권한다.

### 1.2 초록불의 정의 — 이 셋이 다 맞아야 무대에 선다

```
① sim.log 에 `준비 완료` 가 있다
   grep -c '준비 완료' <판>/sim.log        → 1 이상

② 예행 한 판이 합격이다
   python3 simulation/isaac/tools/judge_run.py <판>
   → 합격 · 겹침 0.0 · 옆여유가 +5 mm 넘는다

③ 레벨과 코드가 예행 때와 같다
   판정 출력의 `레벨 <md5> · 코드 <sha>` 를 적어 둔다
```

**③ 을 적어 두는 이유**: 무대 판이 이상하면 제일 먼저 볼 것이 "예행과 같은
것을 돌리고 있나" 다. 기억에 의존하면 그 자리에서 확인이 안 된다.

### 1.3 예행에서 합격이 안 나오면 — 무대에 서지 않는다

한 판 더 돌린다. 두 판 연속 불합격이면 **구성이 바뀐 것**이다. 순서:

```
1) 옆여유를 본다        5 mm 안쪽이면 서가 책 배치가 예행과 다르다
2) 레벨 md5 를 본다      다르면 레벨이 바뀌었다 — 빈칸 위치가 달라진다
3) 코드 sha 를 본다      다르면 누가 push 한 것을 받았다
```

## 2. 무대 위 — 멈추면 무엇을 하는가

**판단의 기준은 하나다: 10초 안에 다시 움직이기 시작하는가.**

| 증상 | 어디서 보나 | 원인 | 그 자리에서 |
|---|---|---|---|
| 팔이 안 움직이고 로그도 조용 | `man.log` 가 안 늘어난다 | 노드 사망 | **노드만 다시 띄운다** (아래 2.1) |
| 팔이 멈췄는데 로그는 돈다 | `ROTATING_BASE` 에서 멎음 | 회전 | 30초 기다린다 — 이제 `SIM_CANCELLED` 로 끊긴다 |
| `410` 이 뜬다 | 결과 메시지 | **거절이다** | 재시도. 같은 결과면 칸이 바뀐 것 |
| `409` 가 뜬다 | 결과 메시지 | 꽂혔는데 확인 실패 | 그 칸을 점유로 기록하지 않는다 |
| Isaac 창이 사라진다 | — | 기동/런타임 크래시 | **판을 접는다** (2.2) |

### 2.1 노드만 다시 띄우기 — 유일하게 무대 위에서 할 만한 복구

`manipulation_node` 는 Isaac 과 별개 프로세스다. **Isaac 을 살려 둔 채 노드만
다시 띄울 수 있고, 5초쯤 걸린다.**

```bash
kill -INT <man_pid>          # PID 로만 죽인다. 패턴으로 훑지 않는다
ros2 run shelving_manipulation manipulation_node \
  --ros-args --params-file ros2_ws/src/shelving_manipulation/config/manipulation.yaml
```

**손에 책이 들려 있으면 그대로 있다.** 노드는 상태를 잃지만 그리퍼는 안 풀린다
(취소 경로가 `HOLD_GRIP` 이다). 다시 띄운 뒤 `PlaceBook` 을 새로 보내면 된다.

> `pgrep -f` 로 찾지 않는다. 그 패턴이 자기 자신과 부모 셸까지 잡은 적이 있다.
> **PID 를 미리 적어 둔다** — `run_vision.sh` 가 `<판>/sim.pid` 에 남긴다.

### 2.2 판을 접어야 할 때

Isaac 이 죽으면 22초 + 장면 준비가 필요하다. **무대에서 그건 복구가 아니다.**
미리 정해 둘 것:

```
누가 말하는가        멈춘 것을 설명할 사람 (도윤님 / FSM 담당자)
무엇을 말하는가      아래 3절
다음에 무엇을 보여주나  예행 녹화본이 있으면 그것. 없으면 다른 부분으로 넘어간다
```

**이 셋을 미리 안 정해 두면 무대 위에서 정하게 된다.**

## 3. 멈췄을 때 할 말 — 이건 변명이 아니라 사실이다

우리 시스템에는 **일부러 멈추는 자리**가 있다. 그걸 구분해서 말하면 멈춘 것이
오히려 설계의 증거가 된다.

```
410 이 떴다        "빈칸을 찾았는데 확신이 없어서 넣지 않았습니다.
                   억지로 넣으면 옆 책을 밀어냅니다"
                   → **사실이다.** 문턱을 낮춰 통과시키지 않는 것이 우리 원칙이다

409 가 떴다        "넣긴 했는데 제대로 들어갔는지 확인이 안 돼서
                   재고에 반영하지 않았습니다"
                   → **사실이다.** 확인된 것만 기록한다

노드가 죽었다      "소프트웨어 하나가 죽었습니다. 다시 띄웁니다" — 5초
Isaac 이 죽었다    시뮬레이터 자체 문제다. 우리 코드 밖이라는 근거가 있다
                   (breakpad 스택이 GPU 플러그인을 가리킨다)
```

**410·409 를 "실패" 로 말하지 않는다.** 그건 검사가 일한 것이다. 다만
**되는 것처럼 꾸미지도 않는다** — 안 들어간 건 안 들어간 것이다.

```
                            "이것만 켜면" 은 예행에서 할 말이다

```

## 5. 시연 전까지 남은 일 (우선순위)

```
1  완주율 표본을 채운다        지금 조합으로 연속 실행. 배치 지표는 안 봐도 된다
2  띄워 둔 뒤 첫 판 확인       1.1 의 미확인 항목. 30분·1시간
3  노드 사망 재현 시도          고친 경로가 맞는지. 안 나면 "미확인" 으로 적는다
4  예행 녹화본 확보             2.2 의 대비책. 영상은 도윤님·FSM 담당자 영역
5  PID·명령을 손 닿는 곳에      2.1 을 무대에서 찾아 헤매지 않게
```

**1·2 가 실제로 확률을 낮춘다.** 3 은 확인이지 개선이 아니고, 4 는 확률을 못
낮추지만 **멈췄을 때의 손실을 줄인다.**

## 6. 이 문서가 보증하지 않는 것

- **"안 멈춘다" 를 보증하지 않는다.** 16판에 사고 1회를 봤고, 표본이 그것뿐이다.
- 고친 두 가지(노드 사망·회전)는 **고친 뒤 재현되지 않았을 뿐** 확인되지 않았다.
- 여기 적힌 복구 시간(5초·30초)은 **재 본 값이 아니라 설계상의 값**이다.
  예행에서 한 번 해 보고 실제 시간을 적어야 한다.
