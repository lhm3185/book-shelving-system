## 1. 가장 큰 발견 — "책이 안 꽂힌다" 가 아니라 **서가가 없었다**

어제까지 삽입 실패를 팔 문제로 보고 파라미터를 만지고 있었다. 실제로는:

- 로봇은 월드 x ≈ **−5.77**, 서가는 x **−2.97 ~ +3.28**. 즉 **로봇 앞에 서가가 없었다.**
- 팔은 계약 좌표까지 책을 정확히 옮긴 뒤 **허공에 놓고** 있었다. 책은 받침판 위로 떨어졌다.
- 검증 코드는 "목표점과 실제 위치 차이" 만 봤기 때문에 이것을 **좌표 오차로 보고**했다.

> **교훈**: 검증이 "숫자가 얼마나 다른가" 만 보면, **세계가 비어 있는 것**을 못 잡는다.
> 목표점에 **받쳐 줄 것이 실제로 있는지**를 따로 확인해야 한다.

## 2. 레벨에 대한 두 가지 사실 (둘 다 눈으로는 안 보인다)

### 2-1. 서가 16개 중 **콜라이더가 있는 건 1개뿐**

```
shelf_brown__book_shelf_01   콜라이더 1개   ← 이것만 물리적으로 존재
나머지 15개                   콜라이더 0개   ← 눈에만 보이는 장식
```

실제로 `_05` 앞에서 삽입했더니 책이 서가를 **통과해 바닥까지** 떨어졌다
(x·y 는 맞고 z 만 1.03 m 낮음). 광선을 쏴 보고서야 알았다 —
`_05` 로 쏜 광선은 전부 바닥면(z 0)까지 갔다.

### 2-2. 서가는 **뒤판이 없다**

양쪽에서 쏜 광선이 둘 다 관통한다. 그래서 "열린 면" 을 광선으로 찾으려던 시도는 실패했고,
대신 **통로가 있는 쪽**을 사람이 골라야 한다.

> **교훈**: 시각 에셋은 **물리적으로 존재한다는 보장이 없다.**
> "보이니까 있다" 는 가정은 시뮬레이터에서 특히 위험하다.

## 3. 로봇이 바뀌면 **같은 선반 단도 다른 좌표가 된다**

선반판 실측 (광선): 월드 z **0.498 / 1.042 / 1.581 / 2.058**

| 로봇 | 팔 베이스 월드 z | 쓰던 단 | 팔 기준 삽입 z |
| --- | --- | --- | --- |
| Franka | 0.28 | 0.498 | **+0.3399** |
| M0609 결합체 | 0.655 | 0.498 | −0.039 (받침판보다 낮아 부적합) |
| M0609 결합체 | 0.655 | **1.042** | **+0.5056** |

계약 좌표는 `arm_base_link` 기준이라 **로봇 키가 바뀌면 같은 물리적 칸이 다른 숫자**가 된다.
계약값 0.3399 를 그대로 쓰면 두 단 사이 **허공**을 가리킨다.

추가로 x 도 옮겨야 했다: 기존 4칸을 그대로 쓰면 가장 먼 −0.5097 에 IK 해가 없었다
(닿는 대역 −0.48 ~ −0.18). 간격 0.08 을 유지한 채 전체를 +0.04 옮겨 **4/4** 가 됐다.

## 4. 오늘 만든 도구 — **자기검증을 넣은 것과 안 넣은 것의 차이**

### 4-1. `place_robot_at_shelf.py` (서가·받침판·팔 베이스를 실측해 로봇을 세운다)

웹 클로드 v19 의 삼종 자기검증을 그대로 넣었다. 그 덕에 **첫 실행에서 두 가지 버그를 잡았다**:

| 검증 | 잡은 것 |
| --- | --- |
| ① 왕복 자기일치 | 옮긴 뒤 다시 재니 **10.6 mm, yaw 0.6° 오차**. 원인: 물리를 켠 채 옮겨 로봇이 주저앉았다 → 물리 없는 스테이지에서 옮기도록 고침 → **0.0 mm** |
| ② 오답 주입 | 여유를 −5 cm 로 주면 겹침을 잡아내는지 확인 (통과) |
| ③ 0 가정 깨기 | 로봇 5.85 m, 서가 3.53 m — 둘 다 원점이 아님을 확인 |

최종: 팔 베이스 [2.922, −3.019, 0.655], yaw 0, 받침판–서가 여유 **정확히 4.8 cm**.

### 4-2. 반대로, **자기검증을 안 넣은 진단은 세 번 연속 틀렸다**

오늘 "무엇이 팔을 막는가" 를 알아내려고 만든 진단이 **세 번 잘못된 답**을 줬다:

| 시도 | 답 | 왜 틀렸나 |
| --- | --- | --- |
| 1차: 링크 AABB 겹침 (자식 포함) | "link_2 가 트레이와 겹친다" | `compute_aabb` 는 Xform 의 **하위 트리를 늘 포함**한다 → link_2 안에 그리퍼가 들어가 "그리퍼가 트레이에 있다" 는 당연한 답 |
| 2차: `include_children=False` | 결과가 **완전히 동일** | Xform 에서는 그 옵션이 안 먹는다 |
| 3차: PhysX overlap, 로봇 몸체 제외 | "팔 주변에 책밖에 없다" | **받침판·AMR 몸체를 내가 걸러냈다** — 정작 의심해야 할 대상 |

세 번째 필터를 풀고 나서야 `Nova_Carter_ROS/Cube`(받침판)와 `bs_tray/book_tray/Cube`(트레이)가
어깨 옆에 있다는 게 보였다.

> **이게 오늘 가장 값비싼 교훈이다.**
> 도구가 "문제 없음" 이라고 답할 때, **그 도구가 그 문제를 볼 수 있는지**를 먼저 물어야 한다.
> 세 번 다 "없다" 는 답이 나왔지만 세 번 다 **볼 수 없어서 없다고 한 것**이었다.
>
> v19 의 삼종 검증에 이걸 하나 더 붙이고 싶다:
> **④ 음성 대조(negative control) — 있는 줄 아는 것을 일부러 보게 해서, 도구가 그걸 잡는지 본다.**
> 오늘이라면 "받침판은 분명 팔 옆에 있다. 내 진단이 그걸 보고하는가?" 를 먼저 물었어야 했다.

## 5. 지금 막혀 있는 지점 (내일로 넘어간다)

**서가 앞 배치에서 `approach` 가 끝나지 않는다.** 증상이 매우 일정하다:

```
경유점 62/62 (끝까지 감)   최대오차 0.14~0.16 rad   허용 0.08
현재 [2.809, 0.546, 1.445, -1.777, -1.859, -0.602]
목표 [2.812, 0.705, 1.438, -1.764, -1.859, -0.601]
                ^^^^^ joint_2(어깨)만 못 간다
```

배제한 것 (전부 실측으로):

| 의심 | 결과 |
| --- | --- |
| 서가와 충돌 | **아니다** — 모든 링크가 서가 앞면에서 13.5 cm 이상 |
| 구동 게인 (1e7/1e5) | **아니다** — 에셋 기본값으로도 똑같이 0.14 rad 부족 |
| 관절 한계 | **아니다** — joint_2 는 ±360° |
| 링크 질량 이상 | **아니다** — 팔 합계 28.5 kg, 중력 토크 ~110 Nm (최대힘 9600) |
| 이웃 책 | **아니다** — 책을 1권만 둬도 동일 |
| 받침판 | **아니다** — 빈 레벨에서는 받침판이 있어도 같은 자세에 도달 |
| **`book_scene` 이 만드는 트레이 구조물** | **여기가 남았다** — overlap 에 `bs_tray/book_tray/Cube` 가 어깨 옆에 잡힌다 |

곁가지로 알아낸 것:
- USD `DriveAPI` 값은 **도(°) 단위**라 런타임에서 **57배**가 된다.
  1e7/1e5 → 실제 5.73e8/5.73e6. 최대힘 9600 과 겹치면 관절이 지령을 못 따라가는 구간이 생긴다.
- `--start-home move` 는 900스텝에서 매번 실패한다. `snap`(순간이동)은 오차 0.0012 rad 로 성공.
  **첫 동작이 실패하면 그 뒤 모든 동작이 "먼 거리 이동" 이 되어 연쇄로 시간 초과**가 난다.

## 5-2. 비전 쪽 변경이 내일 시연에 주는 영향 (오늘 확인)

`origin/vision` 에 오늘 3개 커밋이 올라왔다. 우리에게 영향 있는 것:

| 항목 | 이전 | 지금 | 우리 영향 |
| --- | --- | --- | --- |
| `target_frame` / `slot_position_frame` | `arm_base_link` | **`base_link`** | **계약 위반** — 우리 노드는 `arm_base_link` 아니면 410 으로 거절한다. 게다가 결합체에서 `base_link` 는 **AMR 몸체**라 팔 기준과 데크 높이(0.655 m)만큼 어긋난다 |
| `camera_frame` | `sim_camera` | `RSD455` | 마지막 커밋에서 **프레임 이름 불일치를 치명적 오류로 안 보도록** 고쳐 실질 위험은 사라졌다 |
| `show_debug_window` | true | **false** | 시연용 CV 창이 기본으로 꺼짐 (파라미터로 켜면 됨) |
| 모델 파일 | 외부 절대경로 | 패키지 동봉 | 좋아졌다 — "담당자 PC 에만 있는 경로" 문제 해소 |

**"책 등 중앙 빨간 점 + 파지점" 기능은 아직 어느 브랜치에도 없다** (원격 8개 브랜치 전수 확인).
지금 올라온 빨간 점은 **책이 아니라 서가 빈 단 중심** 표시다.

> **교훈(팀 계약)**: 좌표 계약은 문서가 아니라 **코드의 기본값**에 산다.
> `arm_base_link` → `base_link` 한 줄이 조용히 바뀌면 통합 당일에야 410 으로 나타난다.
> 계약 프레임을 **양쪽 테스트가 같이 검사**하도록 만들어야 했다.
