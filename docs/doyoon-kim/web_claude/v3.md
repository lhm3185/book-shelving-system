## 3. 구간별 성능 — 여기서 약점이 드러났다

겹침 데이터 200장, 인스턴스 809개 기준.

### 가림 구간별

| 가림 | 개수 | Recall | 평균 IoU |
| --- | --- | --- | --- |
| 0~10% | 471 | 83.0% | 0.830 |
| 10~30% | 117 | 82.9% | 0.796 |
| 30~50% | 63 | **96.8%** | 0.880 |
| 50%+ | 158 | 53.2% | 0.525 |

**이상한 패턴이다.** 가림이 적은 0~10% 구간(83.0%)이 30~50% 구간(96.8%)보다 낮다.
가림이 성능을 좌우하는 주 요인이 아니라는 뜻이다.

### 크기별로 다시 나눠 보니 원인이 나왔다

| 마스크 크기(픽셀) | 개수 | Recall |
| --- | --- | --- |
| ~2,000 | 81 | **38.3%** |
| 2,000~10,000 | 283 | 91.2% |
| 10,000~40,000 | 311 | 76.2% |
| 40,000~ | 134 | 79.9% |

**작은 객체에서 Recall 38.3%로 급락한다.** 화면에서 작게 보이는 책(멀리 있거나 심하게 가려진 것)을
놓친다. 전체 mAP 0.99 뒤에 완전히 가려져 있던 약점이다.

10,000~40,000 구간이 40,000+ 구간보다 낮은 것도 눈에 띈다. 큰 객체가 화면을 가득 채우면
경계가 잘려 IoU 0.5 기준을 못 넘기는 경우가 섞인 것으로 보인다(미확인).

### 이것이 CP1 에 주는 의미

다행히 **파지에는 치명적이지 않다.** 로봇은 한 번에 한 권만 집고, 대상은 항상 가장 가까운(= 크게 보이는)
책이다. 작은 객체를 놓치는 것은 "지금 집을 대상"이 아니라 "멀리 있는 다른 책"을 놓치는 것이다.

다만 **"트레이에 책이 몇 권 남았는가"를 세는 용도로는 쓸 수 없다.** 그런 판단이 FSM 에 필요하다면
다른 방법(RFID 수량, 깊이 기반 군집)을 써야 한다.

## 4. 파지 대상 선택 규칙 검증

회신에서 제안한 "탐지된 것 중 깊이 중앙값이 가장 작은 것(최상단)을 집는다" 규칙을 구현해 측정했다.

**정확도 148/200 = 74.0%** (예측 중 가장 가까운 것이 정답 최상단과 일치하는 비율)

74%는 낮다. 원인 후보 세 가지이고 아직 가려내지 못했다.

1. 최상단 책 자체를 탐지 못 한 경우 (위 3절의 미탐지)
2. 탐지는 했으나 bbox 안의 깊이 중앙값이 옆 책·바닥에 오염된 경우
   → **bbox 대신 인스턴스 마스크 안에서 깊이를 재야 한다.** 현재 구현이 bbox 를 쓰고 있다
3. 정답 최상단 판정 기준(라벨의 median_depth_m)과 예측 판정 기준이 다른 경우

**2번이 가장 유력하다.** 세그멘테이션 마스크가 있는데 bbox 로 깊이를 잰 것은 구현 실수에 가깝다.
수정하면 상당히 올라갈 것으로 본다. 이 수정은 비전 담당자에게 인계한다.

## 5. 자세 추정 개선 (회신 권고 적용)

| 항목 | 기존 PCA | 개선 후 | 변화 |
| --- | --- | --- | --- |
| 법선 오차 중앙값 | 3.24° | **1.19°** | 63% 감소 |
| 법선 90% | 10.02° | 8.27° | 개선 |
| 장축 오차 중앙값 | 3.01° | **0.49°** | 84% 감소 |
| 장축 실패율(30°↑) | 11.5% | 10.6% | 소폭 개선 |
| 법선 실패율(30°↑) | 3.5% | **5.3%** | **악화** |
| 중심 오차 중앙값 | 5.23mm | 5.23mm | 동일 |

구현하며 만난 함정 셋:
1. 침식한 점군으로 중심까지 계산하면 중심이 흔들린다 → **침식은 평면 적합에만** 사용
2. RANSAC 이 옆면을 고르면 법선이 90° 어긋난다 → PCA 법선과 30° 이상 벗어나면 기각
3. OpenCV `minAreaRect` 각도 규약이 버전마다 다르다 → 꼭짓점에서 가장 긴 변을 직접 계산

**법선 실패율이 3.5%→5.3% 로 악화된 것이 남은 문제다.** 기각 규칙을 넣었는데도 옆면을 고르는
경우가 남아 있다. 평면 inlier 비율을 추가 조건으로 걸면 줄어들 것으로 보이나 미검증이다.

## 7. 웹 클로드에게 묻고 싶은 것

1. **작은 객체 Recall 38.3% 를 개선할 가치가 있나?**
   CP1 관점에서는 "지금 집을 책"만 맞히면 되므로 무시해도 된다고 판단했다.
   그런데 트레이 잔량 파악 등 다른 용도가 생기면 문제가 된다.
   개선한다면 imgsz 를 960 으로 올리는 것과 작은 객체를 더 많이 생성하는 것 중 어느 쪽이 효율적인가?

2. **최상단 선택 74%** — 4절의 2번(마스크 대신 bbox 로 깊이 측정) 수정으로 충분할까,
   아니면 규칙 자체를 바꿔야 하나? (예: 마스크 상위 10 퍼센타일 깊이, 또는 법선이 카메라를 향하는 정도 가중)

3. **법선 실패율 악화(3.5%→5.3%)** — RANSAC 이 옆면을 고르는 경우를 더 줄이려면
   inlier 비율 조건 외에 무엇을 보는 것이 좋은가?

4. **도메인 갭 측정을 누가 언제 하나.**
   담당이 로봇팔로 바뀌어 Isaac Sim 검증셋 제작을 인계해야 한다.
   인계 문서에 어느 수준까지 적어 두면 비전 담당자가 막히지 않을까?

5. **지표 보고 방식** — 전체 mAP 0.99 만 적으면 오해를 부른다.
   구간별 표를 함께 내는 것이 맞다고 보는데, 발표에서 "약점을 스스로 드러내는" 구성이 감점 요인이 되지는 않나?
