## 1. 무엇이 동작하는가

### 동작 순서 (`--mode spine_out`)

```
홈(데크를 내려다봄) → 책등을 위에서 파지 → 들어 올려 서가 앞으로 운반하며 손목을 90° 세움
→ 앞마구리부터 칸 틈에 끼움 → 놓기 → 손끝이 책등 뒤로 완전히 빠짐
→ 그리퍼를 닫아 책등을 밀어 넣음 → 후퇴 → 홈 복귀
```

### 검증 결과

| 지표 | 값 |
| --- | --- |
| 반복 성공 | **8/8** (책 시작 위치 ±1cm 무작위) |
| 관절 튐 | **0회** (매 스텝 7축 변화량 감시, 기준 0.03 rad/step) |
| 최종 자세 | 선 상태(높이 23.7cm), 깊이 16.3cm, **책등이 서가 앞면에서 2.4cm 안쪽** |
| 반복 정밀도 | 8회 최종 위치가 **2mm 안**에서 일치 |
| 소요 | 약 27초 (1,612 스텝 @ 60Hz) |
| GUI | 재생 버튼으로 시작, 정지 후 재생하면 초기 상태로 되돌려 재실행. 실행 중 정지 3개 시점 검증 |

## 2. 해결한 문제 — 대부분 "수치는 정상인데 동작이 틀린" 유형

| # | 증상 | 원인 | 조치 |
| --- | --- | --- | --- |
| 1 | 허공을 집음 | 책 USD 원점이 실제 책에서 **37cm** 떨어져 있음 | 목표를 AABB 중심 기준으로 |
| 2 | 목표가 전부 어긋남 | Lula IK 가 로봇 베이스 위치를 모름 | `set_robot_base_pose(panda_link0)` |
| 3 | 파지 전에 책이 누워 있음 | 얇게 세운 책이 스스로 넘어짐 (step 45 캡처로 확인) | 칸막이 |
| 4 | 손목 세울 때 관절이 뒤집힘 | 넣는 위치가 팔 원점에서 10cm → **팔꿈치 한계(-3.05/-3.07)** | IK 비교로 옆 35cm 선택 (최대 점프 2.00 → 0.43 rad) |
| 5 | 운반 중 책이 손 안에서 돎 | 손목을 세우면 책이 옆으로 튀어나와 마찰로 못 버팀 | **파지 시 fixed joint** (지침 허용 방식) |
| 6 | **사용자가 GUI 에서 튀는 동작 목격** | 실행 중 매 스텝 IK 를 새로 풀어 해의 가지가 바뀜. **15스텝 캡처로는 안 잡혔다** | 매 스텝 관절 감시로 재현(38회) → **실행 전 5mm·2° 간격으로 경로를 미리 풀고 관절 보간만 실행** → 0회 |
| 7 | 반복하면 6회 중 2회 책이 딸려 나옴 | 뒤로 빠지는 **도중에** 그리퍼를 닫아 손가락이 표지를 감싼 채 닫힘 | 완전히 빠진 뒤 닫도록 경로 분리 → 8/8 |
| 8 | GUI 정지 버튼에 프로그램 종료 | 정지는 스텝 안에서 처리되는데 스텝 전에만 확인 | 스텝 직후 확인 + 예외 시 창 유지 |

**6·7번은 한 번 성공한 뒤에 나왔다.** 6번은 사람이 봐야 했고, 7번은 반복 시험에서만 드러났다.
그래서 **"튐 0회"와 "반복 N회"를 성공 조건에 넣었다.**

## 4. 통합 전 간극 — 판단이 필요한 부분

### 4-1. 실행 위치가 문서와 다르다 ← 가장 큼

| | 팀 문서 | 현재 구현 |
| --- | --- | --- |
| 실행 PC | **PC B** 의 `shelving_manipulation` 노드 | **PC A(GPU PC)** 의 Isaac Sim 스탠드얼론 스크립트 |
| 호출 | FSM → `PlaceBook` 액션 | 스크립트가 직접 실행 |
| 모션 | runbook 에 **MoveIt** 언급 | Lula IK + 자체 관절 경로 계획 |

동작 정의(`arm_primitives.py`)는 백엔드를 갈아끼우는 구조라, **어느 쪽이든 동작 로직은 재사용**된다. 문제는 경계다.

- 안 A: PC B 에 `PlaceBook` 서버 → ROS2 브리지로 관절 목표 발행 → Isaac 이 추종
- 안 B: Isaac 스크립트 안에 `PlaceBook` 서버를 두고 PC A 에서 실행 (문서와 PC 배치가 달라짐)

### 4-2. 좌표계 이름

팀 TF 는 `arm_base_link → tool0 → gripper_tcp`, Franka 는 `panda_link0 → panda_hand → right_gripper`.
`TargetSlot` 은 `arm_base_link` 기준 권장인데 지금은 월드 좌표로 계산한다. **이름 매핑과 변환 정의가 필요하다.**

### 4-3. `PlaceBook` 이 책 인식까지 포함한다

피드백 첫 단계가 `DETECTING_BOOK` 이다. 지금은 시뮬 정답 AABB 를 쓴다.
공식 문서의 1차 전제("책은 트레이 고정 위치")를 따르면 **1차는 알려진 위치 사용이 허용**된다고 본다.

### 4-4. 홈 자세 ≠ 주행 안전 자세

사용자 요청으로 홈을 "데크를 내려다보는 자세"로 바꿨다. 팀 문서는 **"AMR 이동 중 주행 안전 자세 유지"**를 요구한다.
홈과 `stow` 를 분리해 두었고, **stow 는 아직 Isaac 에서 검증하지 않았다.**

### 4-5. 시뮬 전용 요소

fixed joint 파지, 칸막이, 선반 1.4배는 **시뮬을 성립시키기 위한 선택**이다. 보고서에서 숨기지 않고 근거와 함께 쓸 예정이다.
