## 0. 이 문서를 읽는 웹 클로드에게

B-1팀 "도서 자동 배가 시스템"(10일, 시뮬 전용, Isaac Sim 5.1 + ROS 2 Jazzy)의 진행 기록이다.
**CLI 클로드가 실제로 실행하고 측정한 값만 담았다.** 추정과 사실을 구분해 표기했다.
조언이 필요한 지점은 7절에 모았다.

v1 이후 바뀐 큰 것 두 가지:
1. **시스템 설계 확정** — RFID + DB 가 책 신원과 목적 서가를 제공한다. 비전은 위치·자세·두께만 담당한다.
2. **담당 변경** — 작성자가 AMR+로봇팔 중 **로봇팔** 담당이 되었다. 비전 데이터 작업은 일단락되었고,
   내일 아키텍처 확정 후 로봇팔 구현에 들어간다.

## 1. 완성한 것 — 합성 학습데이터 파이프라인

블렌더에서 책을 자동 촬영해 **라벨이 이미 붙은** 데이터를 만든다. 사람이 박스를 그리지 않는다.

### 한 권짜리 데이터셋

| 항목 | 값 |
| --- | --- |
| 규모 | **840장** (9개 에셋, 21권), 약 730MB |
| 구성 | 컬러 + 깊이(uint16 mm) + 마스크 + 라벨 JSON, 누락 0건 |
| USD | 21개 (Isaac Sim 투입용) |
| 화면 점유 | 가로 중앙값 34%, 완전히 보임 66% / 일부 잘림 34% |

### 여러 권 장면 데이터셋 (CP1 검증용, 신규)

| 항목 | 값 |
| --- | --- |
| 규모 | 장면 80개, **인스턴스 302개** |
| 장당 책 | 평균 3.77권 (2~6권) |
| 자세 | 눕힌 책 86%, 쌓인 책 34% |
| 가림 분포 | 가림 없음 29% / 10%↑ 30% / **30%↑ 13% / 50%↑ 9%** |

무인반납기 트레이에 여러 권이 쌓여 나오는 상황을 재현한 것이다.
가림이 심한 사례가 9% 있어 "겹친 책 중 한 권만 분리"하는 능력을 실제로 시험할 수 있다.

### 검증 결과 (측정값)

| 항목 | 결과 |
| --- | --- |
| 좌표 투영 오차 | **0.00px** (블렌더 자체 투영 함수와 대조) |
| bbox 정확도 | 마스크 실루엣 기준. 3D 박스 투영 대비 면적비 중앙값 1.027배, 2배 초과 1.07% |
| 자세 추정 (PCA) | 중심 **5.13mm**, 법선 **3.37°**, 장축 **1.95°** (중앙값, 553장) |
| | 중심 10mm 이내 80.8%, 법선 30° 초과 실패 2.0% |
| 단위 테스트 | 20개 통과 (블렌더 없이 실행) |
| YOLO 학습 | CPU 스모크 테스트 통과 (파이프라인 전 구간 동작 확인) |

## 3. 오늘의 실패와 교훈 (기술 노트감)

### 데이터를 두 번 폐기했다

**1차 폐기 (692장)** — 화각 불일치
학습 데이터는 블렌더 기본 39.6°, 추론은 Isaac Sim 90.5°였다. 화각이 2배 이상 다르면
같은 책도 원근이 완전히 달라진다. 해상도보다 화각 일치가 중요하다는 것을 놓쳤다.

**2차 폐기 (840장)** — 프레이밍 실패
화각을 90.5°로 고쳤더니 이번엔 책이 화면의 **23%만** 차지했다.
거리 자동 계산식이 이전 화각 기준이었고 화각을 반영하지 않았다.

**핵심 교훈**: 두 경우 모두 **수치 검증은 전부 통과했다**. 투영 오차 0.00px, 깊이 일치,
bbox IoU 0.967. 그런데도 학습에 못 쓰는 데이터였다. 샘플 이미지를 눈으로 본 뒤에야 발견했다.
합성 데이터는 수치 검증과 육안 확인이 **둘 다** 필요하다.

### 블렌더 5.x API 변경으로 여러 번 막혔다

문서나 기억에 의존하면 틀리는 것들이다. 실행으로 하나씩 확인했다.
- `scene.node_tree` 제거 → `scene.compositing_node_group`
- `Composite` 노드 제거 → Group Output
- File Output: `base_path`/`file_slots` → `directory`/`file_name`/`file_output_items`,
  **멀티레이어 EXR 만 지원** (그래서 깊이를 16비트 PNG 로 우회)
- `CompositorNodeMath` → `ShaderNodeMath`
- **EEVEE 는 오브젝트 인덱스 패스를 지원하지 않는다** (Cycles 전용)

마지막 항목 때문에 인스턴스 마스크를 다른 방법으로 만들었다.
책마다 깊이를 따로 렌더해 장면 깊이와 비교하는 방식인데, 결과적으로 **가림 비율을
추정이 아니라 정확한 값으로** 얻게 되어 더 나은 결과가 되었다.

## 5. 로봇팔 담당 관련 (신규)

팀 요청: **픽앤플레이스·기본동작을 단위로 묶어 정의하고 호출하는 방식**으로 구현.
동선과 속도까지 그 단위에 포함. 목적은 merge 충돌 방지.

동의하되 아래를 보완하기로 했다.

1. **블로킹 금지** — Isaac Sim 스탠드얼론은 매 스텝 `world.step()` 을 도는 단일 루프다.
   동작이 끝날 때까지 기다리면 시뮬이 멈춘다. `enqueue` → 매 스텝 `update()` 구조로 간다.
2. **계약 문서화** — 이름만 맞추면 시그니처 변경 때 또 충돌한다.
   인자·단위·좌표계·반환값·제한 시간을 문서로 고정하고 변경은 전원 합의.
3. **속도·높이는 `arm_config.yaml` 로 분리** — 코드에 박으면 튜닝마다 같은 줄이 충돌한다.
4. **FSM 로직 분리** — 동작 단위는 "어떻게", FSM 은 "언제 무엇을".
5. **실패 처리 내장** — 제한 시간, IK 실패·미도달 시 사유 반환, 무한 재시도 금지.
6. **시뮬 없는 테스트** — mock 실행기로 GPU 없이 동선 로직 검증.

아키텍처 확정 후 인터페이스 정의부터 진행할 예정이다.

## 7. 웹 클로드에게 묻고 싶은 것

1. **도메인 차이 (v1 에서 이어짐, 여전히 미해결)**
   학습은 블렌더 렌더, 추론은 Isaac Sim 렌더다. 화각은 맞췄지만 렌더러가 다르다.
   Isaac Sim Replicator 로 다시 만드는 게 맞나, 블렌더 데이터에 랜덤화를 더 넣는 쪽이 현실적인가?
   남은 기간은 10일 중 후반부다.

2. **겹침 데이터의 가림 임계값**
   `--max-occlusion` 으로 "이 비율 이상 가려진 객체는 학습에서 제외"를 정한다.
   현재 0.85 로 잡았는데, 너무 낮으면 겹침 상황을 못 배우고 너무 높으면 보이지도 않는 것을
   맞히라고 시키는 꼴이 된다. 권장값과 근거가 있나?

3. **PCA 자세 추정의 한계**
   학습 없이 마스크+깊이 PCA 로 파지 자세를 구해 중심 5.13mm, 법선 3.37° 를 얻었다(한 권 기준).
   겹쳐 쌓인 상황에서는 옆 책과 경계가 깊이로 구분되지 않아 두께를 과대평가할 위험이 있다.
   보완책이 있나? (인스턴스 마스크가 있으므로 마스크로 점군을 자르는 것은 이미 하고 있다)

4. **로봇팔 동작 단위 설계 검토**
   5절의 구조(비블로킹 프리미티브 + 큐 + 스텝 구동)가 Isaac Sim + ROS 2 환경에서 타당한가?
   Nav2 로 AMR 이 움직이는 것과 팔 동작을 어떻게 조율하는 것이 좋은가?
   (현재 가정: "정지 → 촬영 → 판단 → 동작" 순서 고정, 동시 동작 없음)

5. **평가 지표**
   발표·보고서에 넣을 정량 지표로 무엇이 적절한가?
   현재 후보: 파지 성공률, 자세 추정 오차(mm/도), 가림 비율별 탐지 성공률,
   관측 자세 이동 시간(브리프에서 요구), 5회 연속 실행 성공률.
