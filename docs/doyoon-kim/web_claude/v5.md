## 1. 수치 불일치 — 규명 완료

지적: "mAP50 0.99와 저가림 구간 Recall 83%는 같은 모델의 같은 난이도에서 나올 수 없다."

**맞다. 두 숫자는 서로 다른 집단을 재고 있었다.**

### 세 가설 측정 결과

| 가설 | 결과 |
| --- | --- |
| ① GT에 학습 제외분(가림 0.85 초과)이 남아 있다 | **부분 확인** |
| ② 신뢰도 임계값 차이 | **부분 확인** |
| ③ 겹침 장면이 학습 분포 밖이다 | **기각** |

**가설 ③ 기각**: train 3,510장 중 겹침 360장, valid 345장 중 45장, test 345장 중 45장.
겹침 장면은 학습에 포함되어 있었다.

**가설 ① 측정** — GT에 학습과 동일한 0.85 필터 적용:

| 구간 | 필터 전 | 필터 후 |
| --- | --- | --- |
| 가림 50%+ | 53.2% | **72.8%** |
| 마스크 ~2,000px | 38.3% (81개) | **62.1%** (29개) |

**"작은 객체 약점"의 상당 부분은 학습에서 제외한 것을 평가에서 세고 있던 것이었다.**
지적대로 작은 마스크와 고가림은 같은 현상의 두 측면이었고, 두 표가 같은 집단을 두 번 세고 있었다.

**가설 ② 측정** — conf 0.25 → 0.05 (GT 필터 유지):

| 구간 | conf 0.25 | conf 0.05 |
| --- | --- | --- |
| 0~10% | 83.0% | 86.0% |
| 10~30% | 82.9% | 86.3% |
| 30~50% | 96.8% | 100.0% |
| 50%+ | 72.8% | 75.0% |

효과는 있으나 3pt 수준이다. 이것만으로는 설명되지 않는다.

### 진짜 원인 — 평가 집단이 달랐다

**ultralytics가 보고한 mAP 0.994는 valid 345장 기준인데, 그중 겹침 장면은 45장(13%)뿐이다.**
나머지 87%는 책 한 권짜리 쉬운 이미지다. 반면 우리 구간별 평가는 **100% 겹침 장면**이었다.

겹침 장면만으로 표준 평가를 다시 돌렸다(450장, 1,501 인스턴스).

| 지표 | 전체 valid (87% 단권) | **겹침 장면만** |
| --- | --- | --- |
| Box mAP50 | 0.994 | **0.957** |
| Box mAP50-95 | 0.978 | **0.898** |
| Box Recall | 0.985 | **0.895** |
| Mask mAP50 | 0.992 | **0.934** |
| Mask mAP50-95 | 0.963 | **0.846** |

**모순이 아니라 난이도 차이였다.** 겹침 장면에서 Recall 0.895 이고, 우리 커스텀 평가의 83~86%는
고정 신뢰도 + IoU 0.5 단일 매칭이라는 더 엄격한 조건에서 나온 값이다. 두 값은 일관된다.

### 보고할 때 쓸 문장

> 전체 valid 기준 mAP50 0.994. 다만 이 집단은 87%가 단권 장면이다.
> **겹쳐 쌓인 장면만으로 재측정하면 Box mAP50 0.957 / Mask mAP50 0.934 / Recall 0.895** 이다.
> CP1 이 다루는 조건은 후자이므로 이 값을 기준으로 판단해야 한다.

## 2. 새로 발견한 결함 — 중복 라벨 14%

겹침 데이터를 YOLO 로 변환할 때 **같은 영역을 가리키는 라벨이 중복 생성**되고 있었다.
450장 중 104장에서 252줄 중복 (전체 1,770줄의 14%).

### 원인

인스턴스 두 개의 bbox 가 완전히 동일했다.

```
index=1 book_softcover_01_cover01  px=26234  bbox=[0,0,416,325]
index=2 book_hardcover_01_cover02  px=27135  bbox=[0,0,442,358]
index=3 book_softcover_01_cover04  px=25385  bbox=[0,0,416,325]   ← 1번과 동일
```

**서로 다른 책이 같은 자리에 겹쳐 배치됐다.** 쌓기 로직에서 두 책이 관통한 경우다.
두 책의 깊이가 거의 같으니 "가려지지 않았다"는 판정을 둘 다 통과해 각각 온전한 마스크를 갖는다.

### 조치

- **변환 단계에서 중복 제거**를 넣었다(같은 영역이 이미 있으면 건너뛰고 경고 출력). 확인됨
- **배치 로직 수정은 하지 않았다.** 겹침 검사가 같은 높이(`z` 차이 0.01m 이내)일 때만 동작하는데,
  쌓기 경로에서는 높이가 다르다는 이유로 통과해 버린다. 인수인계 문서에 알려진 결함으로 적었다

### 영향 평가

중복 라벨은 같은 위치를 두 번 학습시키므로 **그 위치의 신뢰도를 과대평가**한다.
다만 위치 자체는 맞으므로 심각한 오염은 아니다. 재학습 여부는 도메인 갭 측정 뒤에 판단하는 것이
순서라고 본다(갭이 크면 어차피 재학습한다).

## 3. 회신에 대한 이견과 보완

### 3-1. A1 "관측 자세 표준화" — 동의하나 순서를 바꾸고 싶다

제안한 순서는 ①GT 필터 ②conf 스윕 ③관측 자세 표준화 ④데이터 재생성 ⑤imgsz 960 이었다.
①②는 완료했고 결과는 위와 같다.

**③을 지금 확정하기 어렵다.** 관측 자세는 로봇팔·AMR 담당과 합의해야 하는 시스템 설계 사항이고,
아직 아키텍처가 확정되지 않았다. 비전 담당자 혼자 정할 수 없다.

대신 **인수인계 문서에 "관측 자세가 정해지면 그 거리 대역으로 데이터를 재생성하라"**고 적었다.
파이프라인이 `--dist MIN MAX` 를 받으므로 한 줄로 끝난다.

### 3-2. A2 "74%는 시스템 실패율이 아니다" — 전적으로 동의한다

지표를 잘못 정의했다. 깊이 순위 분포(1위/2위/3위 이하)로 바꾸는 것이 맞다.
다만 **이 수정은 구현하지 못했다.** 담당이 로봇팔로 바뀌어 인수인계 문서에 남긴다.

RANSAC 평면의 중심 깊이를 선택 기준으로 쓰라는 제안은 특히 좋다.
**선택과 자세 추정이 같은 계산에서 나온다**는 일관성 이득이 크다. 문서에 반영했다.

### 3-3. A3 "기권 메커니즘" — 가장 유용한 조언이었다

"실패율 5.3%를 3%로 낮추는 것보다 실패를 미리 알아채는 것이 낫다"는 지적에 동의한다.
다만 **한 가지 확인이 필요하다.**

기권 임계값을 잘못 잡으면 **정상인데 기권하는 경우**가 늘어 사이클 타임이 나빠진다.
"기권 4.8%, 미기권 실패율 0.5%"가 목표라면, 임계값을 어떻게 잡아야 그 균형이 나오나?
평면 품질 점수의 분포를 보고 정하는 것 외에 기준이 있나?

시선 정렬 조건(`|dot(normal, view)| < 0.5` 기각)은 즉시 적용 가능하다고 판단해 문서에 넣었다.

### 3-4. A5 "약점을 드러내는 구성" — 동의. 이미 그렇게 작성했다

발표 구성 5단계(전체 → 분해 → 약점 → 요구사항 대비 영향 → 대응 근거)를 그대로 쓰겠다.

다만 **1절의 규명 결과를 반영해 "약점"의 서술을 바꿔야 한다.**
"작은 객체에 약하다"가 아니라 **"평가 설정이 학습 설정과 달라 생긴 착시가 상당 부분이었고,
정렬 후 남는 것은 겹침 장면에서의 성능 저하(0.994 → 0.957)"** 가 정확한 서술이다.

### 3-5. B1 "웨이포인트로 회피 문제를 없앤다" — 동의한다

(a) 접근점 → (b) 슬롯 정면 정렬 → (c) 직선 전진 → (d) 놓기 → (e) 직선 후퇴 구조가
Lula IK + 직선 보간으로 충분하다는 데 동의한다. `arm_config.yaml` 에 웨이포인트를 정의하겠다.

### 3-6. B3 "흡착 컵 제작" — 동의. 충돌체 제외 주의사항이 특히 유용했다

### 3-7. B4 "힘 한계를 계산해서 넣을 것" — 동의

`F = m × a`, 0.4kg × 1 m/s² = 0.4N, 여유 5~10배 → 2~4N.
`maxGripDistance` 1~2cm 가 자세 추정 중심 오차 5.23mm 보다 크다는 연결도 문서에 넣겠다.

## 4. 남은 질문

1. **기권 임계값 설정 기준** (3-3)

2. **중복 라벨로 인한 재학습 필요성**
   14% 중복은 같은 위치를 두 번 학습시킨 것이다. 도메인 갭 측정 전에 재학습할 가치가 있나,
   아니면 갭 측정 결과를 보고 한 번에 처리하는 것이 맞나?

3. **겹침 장면 비율**
   현재 학습 데이터는 겹침 10%(360/3510), 단권 90% 다. CP1 이 겹침 상황을 다루는데 이 비율이 맞나?
   겹침을 30~50%로 올리면 단권 성능을 해치지 않고 겹침 성능이 오를까?

4. **인수인계 범위**
   담당이 로봇팔로 바뀌어 A2(선택 규칙 개선), A3(기권 메커니즘), A4(도메인 갭)를 모두 넘긴다.
   받는 사람이 우선순위를 잘못 잡을 위험이 있는데, 문서에 "이것만은 반드시"를 몇 개까지 적는 것이 좋나?
   현재는 도메인 갭 최소 버전(30장) 하나만 필수로 표시했다.
