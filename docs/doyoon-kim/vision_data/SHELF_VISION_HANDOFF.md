## 3. 생성할 때 바꾼 것 — 그리고 왜 바꿨는지

책과 같은 설정으로 돌렸더니 **수치는 전부 정상인데 사람 눈에 물체가 안 보이는**
이미지가 절반이었다. 세 가지를 고쳤다.

### 3-1. 카메라 공전 중심을 원점 → 바운딩박스 중심으로 (버그였다)

선반은 **원점이 바닥에 있다.** 원점을 중심으로 카메라를 돌리면 고도각이 음수일 때
카메라가 **바닥 아래로 내려간다.** 그러면 50m 짜리 바닥면이 대상을 통째로 가린다.

깊이 맵으로 잡았다 — 카메라에서 서가까지 2.1 m 인데 마스크 영역의 깊이가 **0.4 m** 였다.
무언가가 40cm 앞에서 가리고 있다는 뜻이고, 그게 바닥이었다.

```python
# 고침: 원점이 아니라 바운딩박스 중심을 쓴다
_corners = [book.matrix_world @ Vector(c) for c in book.bound_box]
center = (sum(c.x for c in _corners)/8, sum(c.y for c in _corners)/8, sum(c.z for c in _corners)/8)
```

책은 원점이 중심에 있어서 이 버그가 드러나지 않았다. **원점이 어디 있는지 모르는 에셋을
쓸 때마다 다시 만날 수 있는 문제다.**

### 3-2. 배경에 벽을 세웠다 (`--backdrop room`)

개방형 서가는 **속이 비친다.** 단색 배경 앞에 두면 얇은 선반판만 남아 사람 눈에도
안 보인다. 그런 이미지로 학습시키면 배경을 물체로 외운다.

대상을 둘러싼 벽 4장에 **체커 무늬**를 넣고 매 프레임 색·크기를 바꾼다.
무늬 스케일은 8~40 이다. 이보다 작으면 가까이서 한 칸만 보여 단색 벽이 된다.

> 벽은 **마스크·깊이에서 제외**된다. `MaskWriter(scene, floor, extras=[walls])` 로
> 마스크 렌더 때 숨긴다. 이 처리를 빠뜨렸을 때는 마스크가 벽 전체를 물체로 잡았다.

### 3-3. 키 라이트를 카메라 쪽에 뒀다 (`--key-follows-camera`)

조명이 카메라 반대편에 놓이면 보이는 면이 전부 그늘이라 배경과 밝기가 같아진다.
첫 번째 조명만 카메라 방위각 ±60° 안에 두고, 나머지는 그대로 랜덤이다.
(완전히 일치시키면 그림자가 사라져 입체감이 없어진다.)

**결과**: 물체-배경 밝기차 중앙값이 15.8 → **32.3** 으로 올랐다 (시험 12장 기준).

### 3-4. 검은 선반이 흰색으로 600장 나왔다 (버그 두 개가 겹쳤다)

전체 생성 후 무작위로 뽑아 보니 **폐쇄형 선반이 전부 흰색**이었다. 라벨·마스크·bbox 는 전부 정상이었다.

| 원인 | 설명 | 고침 |
| --- | --- | --- |
| ① 텍스처가 상대경로 | USD 임포트가 텍스처를 `//../../../../Downloads/textures/…` 로 걸었다. 이 PC 에서는 찾아지지만 **폴더 깊이가 다른 GPU PC 에서는 끊긴다** | `prepare_shelf_from_usd.py` 가 텍스처를 blend 안에 **pack** 한다 |
| ② pack 해도 떼어냈다 | `render_book_dataset.py` 의 `drop_missing_textures()` 가 **pack 여부를 보지 않고 경로만** 확인했다. 그래서 pack 한 뒤에도 끊었다 | `not img.packed_file` 조건 추가 |

①만 고쳤을 때 다시 돌려 봤는데 여전히 흰색이었다. **한 번에 고쳐졌다고 믿지 말고 다시 찍어 볼 것.**
흰색 600장은 폐기하고 다시 생성했다.

> 이 두 버그는 **책 데이터에도 해당된다.** 텍스처 경로가 끊긴 에셋을 다른 PC 에서 렌더하면
> 같은 일이 생긴다. 에셋을 옮길 때는 pack 할 것.

### 3-5. bbox 가 마스크 기준이 아니었다 — "갱신 0장"이 성공이 아니었다

`add_tight_bbox.py` 가 라벨을 `*/*/labels/*.json`(에셋/책/labels) 패턴으로만 찾았다.
선반은 `선반/labels` 한 단계라 **라벨을 하나도 못 찾았고**, 출력은 "갱신 0장"으로 조용히 끝났다.
그래서 bbox 가 마스크가 아니라 **3D 박스 투영값** 그대로 남았다. 화면 가장자리에서 잘린
29장에서 최대 17.7px 어긋났다.

패턴을 `**/labels/*.json` 으로 바꾸고, 라벨을 하나도 못 찾으면 `[error]` 를 내게 했다.
재실행 후 1,200장 전부 `bbox_source: mask`, 마스크와 차이 **0.0px**.

> **"0건 처리"는 성공이 아니라 경고로 읽을 것.** 할 일이 없었던 건지 못 찾은 건지 구분이 안 된다.

## 4. 재생성 방법

```bash
blender -b assets/shelf/shelf_brown.blend -P render_book_dataset.py -- \
    --out dataset_shelf/shelf_open --views 600 --book book_shelf \
    --res 640 480 --hfov 90.5 --no-material-random --no-book-random \
    --elev -10 40 --fill 0.30 0.85 --roll 8 --backdrop room \
    --light-energy 40 150 --key-follows-camera --lights 2 3 --seed 7

python3 add_tight_bbox.py dataset_shelf/shelf_open
```

폐쇄형은 `--book book_shelf_closed`, blend 파일만 바꾸면 된다.

| 옵션 | 왜 이 값인가 |
| --- | --- |
| `--no-book-random` | 서가는 기울어지지 않는다. 책과 달리 자세가 고정이다 |
| `--no-material-random` | 색이 두 에셋의 구분 요소다. 랜덤화하면 의미가 없어진다 |
| `--elev -10 40` | 로봇 눈높이에서 올려다보는 각도까지. 책처럼 위에서 내려다보지 않는다 |
| `--fill 0.30 0.85` | 도킹 후 거리에서 서가가 화면을 채우는 비율 |

## 5. 이 데이터로 할 수 있는 것과 없는 것

### 할 수 있는 것 — CP2 (목표 서가 자율주행·정밀 도킹)

- 서가 **검출**과 **6D 자세 추정** 학습
- 개방형/폐쇄형 **2클래스 구분** (폴더가 나뉘어 있으므로 클래스 라벨을 붙이면 된다)
- ArUco 마커 없이 서가 Pose 를 잡는 2차 목표(`9/22~23 윤재민`)의 기반

### **할 수 없는 것 — CP3 (목표 슬롯 결정·빈자리 확인)**

**슬롯 단위 라벨이 없다.** 이 데이터는 "서가 하나 = 객체 하나" 다.
빈 슬롯을 찾으려면 슬롯마다 라벨이 있어야 하는데 지금은 없다.

슬롯 라벨이 필요해지면 방법은 두 가지다.

1. **기하로 계산** (권장) — 서가는 강체이고 치수를 안다.
   서가 6D 자세를 추정했으면 슬롯 5칸의 3D 위치는 **모델 치수에서 바로 나온다.**
   별도 학습이 필요 없다. 슬롯 중심을 투영해 해당 영역의 깊이를 보면 비었는지 알 수 있다
2. **슬롯을 인스턴스로 렌더** — 겹침 책 데이터(`render_multi_book.py`)에서 쓴
   **책별 깊이를 따로 렌더해 장면 깊이와 비교**하는 방식을 슬롯에 그대로 적용하면 된다.
   슬롯 자리에 보이지 않는 프록시 박스를 놓고 인스턴스 깊이를 뽑는 구조다

**1번을 먼저 시도할 것.** 2번은 데이터 재생성이 필요하고, CP3 요구사항(논리적 점유 상태는
YAML/DB 가 준다)을 보면 비전은 "실제로 비었는지 확인"만 하면 된다.

## 6. 알려진 한계

| 한계 | 설명 |
| --- | --- |
| 배경이 단순하다 | 체커 벽 + 흰 바닥이다. 실제 도서관 배경(다른 서가, 사람, 창)은 없다 |
| 서가에 책이 꽂혀 있지 않다 | **빈 서가만 있다.** 책이 꽂힌 상태는 학습 분포 밖이다 |
| 두 에셋뿐이다 | 형태 다양성이 없다. 다른 서가 모델에 일반화될지는 미검증 |
| 도메인 갭 미측정 | 책과 동일한 문제. Isaac Sim 렌더와 비교한 적 없다 |

**가장 큰 한계는 두 번째다.** 실제 CP2·CP3 에서는 서가에 책이 일부 꽂혀 있다.
빈 서가로 학습한 모델이 반쯤 찬 서가를 얼마나 잘 잡을지 확인이 필요하고,
필요하면 `render_multi_book.py` 처럼 책을 슬롯에 배치한 장면을 생성해야 한다.

## 8. 반드시 지킬 것

**수치 검증만으로는 이 데이터의 문제를 하나도 못 잡았다.** 이번 선반 작업에서만 네 번이다.

| 문제 | 수치 검증 | 발견 방법 |
| --- | --- | --- |
| 카메라가 바닥 아래 → 바닥이 선반을 가림 | 투영 0.00px, 마스크 정상 | 눈으로 봄 → 깊이 맵으로 확정 |
| bbox 가 마스크 기준이 아님 | "갱신 0장" 으로 정상 종료 | 마스크와 직접 대조 |
| 마스크가 벽 전체를 선반으로 잡음 | 개수 정상 | 눈으로 봄 (윤곽 덧그리기) |
| 검은 선반이 흰색 | bbox 오차 1.5px 이내 | 눈으로 봄 (무작위 추출) |

책 데이터에서 두 번(화각·프레이밍), 선반에서 네 번. **여섯 번 모두 스크립트가 "정상"이라고 했다.**

```bash
# 생성 직후 반드시 실행
python3 predict_check.py --source "dataset_shelf/**/images/*.png" --out /tmp/check.png
# 또는 마스크 윤곽을 이미지에 덧그려 격자로 확인
```
