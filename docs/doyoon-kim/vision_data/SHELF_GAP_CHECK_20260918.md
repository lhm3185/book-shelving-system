## 3. 원인 (깊이 실측값)

1.40 m 시점에서 각 단의 깊이 중앙값과, 같은 단을 가로로 5등분했을 때의 값입니다.

| 단 | 단 전체 중앙값 | 가로 5칸 중앙값 | 실제 |
| --- | --- | --- | --- |
| 0 | 1.68 | 1.68 / 1.68 / 1.68 / 1.68 / 1.68 | 빈 칸 |
| **1** | **1.70** | **1.43 / 1.43 / 1.68 / 3.60 / 11.56** | **왼쪽에만 책** |
| 2 | 3.57 | 3.57 / 3.56 / 3.56 / 3.56 / 11.46 | 빈 칸 |
| 3 | 3.48 | 3.48 / 3.48 / 3.50 / 3.48 / 3.50 | 빈 칸 |
| 4 | 1.28 | 1.72 / 1.30 / 1.72 / 1.72 / 0.86 | 빈 칸 (로봇 팔이 들어옴) |

### (1) 서가 뒤가 뚫려 있어 "멀다 = 빈 칸" 이 성립하지 않는다

빈 단의 깊이가 **3.5 m** 로 나옵니다. 서가 안쪽이 아니라 **뒤쪽 벽·다른 서가**를 보고 있는 값입니다.
반대로 책이 있는 단은 1.43 m 입니다. 지금 규칙("가장 가까운 단보다 margin 이상 멀면 빈 칸")은 우연히 맞을 수는 있지만, **기준이 되는 "가장 가까운 깊이"가 오염되면 통째로 뒤집힙니다.**

실제로 4번 단에 **로봇 팔(0.86 m)** 이 들어오면서 기준이 0.86 이 되고, 그 뒤로 모든 단이 "멀다 = 빈 칸" 이 됐습니다.

**제안**: 기준을 "가장 가까운 단" 이 아니라 **서가 앞면 깊이**로 잡고, 빈 칸 판정에 **위쪽 한계**를 두는 것이 안전합니다.

```
빈 칸 = (앞면 + 책 두께 여유) < 깊이 < (앞면 + 서가 안쪽 깊이)
```

이렇게 하면 3.5 m(뒤 배경)는 "빈 칸"이 아니라 "서가 밖"으로 걸러집니다.

### (2) 한 단이 부분적으로 차 있으면 중앙값이 섞인다

1번 단은 **왼쪽 2/5 에 책, 오른쪽 3/5 는 비어 있습니다.** 단 전체 중앙값은 1.70 이라 책도 빈 칸도 아닌 값이 나옵니다.

**로봇팔이 실제로 필요한 것은 "어느 단이 비었나" 가 아니라 "그 단의 어디에 넣을 수 있나"(가로 위치)** 입니다.
단을 가로로도 나눠 칸 단위로 보시면 위 표처럼 **왼쪽=책, 오른쪽=빈 칸**이 그대로 드러납니다.

### (3) 5등분이 실제 단 경계와 맞지 않는다

bbox(y 42~611)를 5등분하면 경계가 실제 선반판과 어긋납니다. 원근 때문에 위쪽 단이 더 얇게 보이고, bbox 에는 맨 위 상판과 아래 바닥(로봇·데크)까지 들어옵니다.
4번 단에 로봇 팔이 들어온 것도 이 때문입니다.

**제안**: 단 경계를 균등 분할 대신 **가로 선반판(밝은 가로줄)** 에서 잡거나, 학습 단계에서 단(row)을 클래스로 두는 방법이 있습니다.

## 4. 다시 시험하려면

```bash
# GPU PC — 깊이·bbox·정답 뽑기 (Isaac)
SIM_USD=~/Desktop/ing_library_env_v5.usd \
ISAAC_ENTRY=isaac_sim/isaac/tools/shelf_gap_probe.py ./scripts/run_isaac_tool.sh \
    --views 4 --dist 1.4 2.2 --out ~/shelf_probe

# 판정 모듈만 돌려 비교 (ROS 없이)
python3 - <<'PY'
import json, numpy as np, sys; sys.path.insert(0, '<shelving_perception 경로>')
from shelving_perception.target_detector import TargetDetector
truth = json.load(open('truth.json')); det = TargetDetector(row_count=5, depth_margin=0.05)
for v in truth['views']:
    d = np.load(v['name'] + '.npz')
    print(v['name'], [s['row_index'] for s in det.find_empty_slots(
        d['depth'], tuple(d['bbox']), float(d['fx']), float(d['fy']), float(d['cx']), float(d['cy']),
        depth_scale=1.0, shelf_class='shelf')])
PY
```

`truth.json` 에 단별 정답이 들어 있어 바로 비교됩니다.

## 5. 저희 쪽에 필요한 것

1. **서가 학습 모델 파일** (`260918_train/best.pt`) — 지금은 bbox 를 정답으로 넣어 시험했습니다. 검출까지 포함해 보려면 모델이 필요합니다
2. `/detect_target_slot` 액션 서버를 구현하신 것 확인했습니다. FSM 과 붙일 때 로봇팔이 받는 규약은 그대로입니다: **`frame_id = arm_base_link`, 위치 = 꽂힌 뒤 책 AABB 중심, 방향 = yaw +90°(z=w=0.7071068)**. 이 규약을 벗어나면 로봇팔이 M410 으로 거절합니다
3. 1차 시연에서 쓸 값은 검증된 4칸 좌표입니다: x = −0.3497 / −0.4297 / −0.5097 / −0.2697, y = 0.5495, z = 0.3399
