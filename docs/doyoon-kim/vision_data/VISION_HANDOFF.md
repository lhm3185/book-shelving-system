# 비전 담당자 인수인계 — 책 인식 파이프라인

> **이 문서를 읽는 사람과 AI 에이전트에게**
> 책 인식용 합성 학습데이터 파이프라인과 학습된 모델을 넘긴다.
> 담당이 로봇팔로 바뀌면서 비전 작업을 이관하는 것이다.
> **이 문서만 읽고 이어서 작업할 수 있게 썼다.** 순서대로 읽을 것.

| 항목 | 값 |
| --- | --- |
| 인계일 | 2026-09-16 |
| 만든 환경 | Blender 5.2.0 LTS, Python 3.12, Ubuntu 24.04 |
| 학습 환경 | RTX 5080, ultralytics YOLO11 |
| 상태 | 데이터 생성·학습 완료. **Isaac Sim 연동 검증이 남았다** |

### 필수는 하나뿐이다 — 나머지는 그 결과에서 도출된다

> **필수: Isaac Sim 도메인 갭 최소 측정 (K 행렬 확인 → 이미지 30장 → mAP 차이 숫자 하나)**

완료 판정은 **"blender-val 과 isaac-val 의 mAP50 차이 숫자 하나"** 다. 그 숫자가 나오면 끝이다.

그다음은 외울 필요 없다. 갭 수치가 정해준다.

```
갭 < 5pt    → 4절 선택 규칙 수정 → 5-3절 기권 게이트
갭 5~15pt   → 증강을 넓혀 재학습 → 그다음 4절
갭 > 15pt   → 데이터 재생성이 최우선.
              이때 겹침 비율 40~50%, 관측 거리 대역을 함께 반영 (5절)
              4·5-3절은 보류
```

**우선순위를 외우지 말고 이 분기를 따를 것.** 갭을 재기 전에 다른 것부터 손대면,
어차피 재생성으로 날아갈 작업에 시간을 쓰게 된다.

### 남은 작업 (우선순위 순)

| 작업 | 절 | **완료 판정** |
| --- | --- | --- |
| **K 행렬 확인 → 도메인 갭 측정** | 2·3 | **blender-val 과 isaac-val 의 mAP50 차이 숫자 하나** |
| 파지 대상 선택 규칙 | 4 | 깊이 순위 **1~2위 비율 90% 이상** (현재 80.2%) |
| 자세 추정 기권 게이트 | 5-3 | 게이트 3개 적용 후 **(기권율, 잔여 실패율) 한 쌍을 기록** |
| 데이터 재생성 | 5 | 갭 > 15pt 일 때만. 겹침 40~50% + 관측 거리 대역 반영 |

숫자가 나오면 끝이다. "더 개선할 수 있을 것 같은데"로 늘어지지 말 것.

### 건드리지 말 것

- **씬 배치 관통 버그** — 변환 단계에서 우회 적용됐다(5-2절). 고치려면 쌓기 로직 전체를
  봐야 하고, 어차피 재생성 시점에 함께 처리한다
- **연속 품질 점수 튜닝** — 실패 사례가 29건뿐이라 과적합된다. 하드 게이트만 쓸 것 (5-3절)
- **imgsz·모델 크기 변경** — 관측 자세가 확정되기 전에는 판단 근거가 없다
- **데이터 추가 생성** — 도메인 갭 결과가 나오기 전까지 보류

### 막히면 물어볼 것

**30분 안에 물을 것. 혼자 2시간 이상 쓰지 말 것.** 같은 팀이고 문서로 다 전달되지 않는다.
인계받았다고 혼자 해결해야 하는 것이 아니다.

## 2. 바꾸면 안 되는 규약

이 값들이 바뀌면 기존 데이터·모델과 맞지 않게 된다. 바꾸려면 팀 합의가 필요하다.

| 항목 | 값 | 이유 |
| --- | --- | --- |
| 가로 화각 | **90.5°** | Isaac Sim USD 손목 카메라 실측값 |
| 해상도 | **640 × 480** | Isaac Sim 은 현재 640×640. **아래 주의사항 참조** |
| 자세 규약 | OpenCV (+Z 앞, +X 오른쪽, +Y 아래), m | 학습 관례 |
| 깊이 | uint16 PNG, **밀리미터**, 65535 = 배경 | RealSense 와 동일 |
| 클래스 | **단일 `book`** | RFID + DB 가 신원·목적 서가를 제공. 비전은 종류를 구분하지 않는다 |

### 주의 — 화각을 믿지 말고 K 행렬로 확인할 것

우리는 **화각 불일치로 데이터를 두 번 폐기했다.** 같은 실수를 반복하지 않으려면
Isaac Sim 이 실제로 발행하는 값을 직접 읽어야 한다.

```bash
ros2 topic echo /wrist_camera/color/camera_info    # 또는 현재 토픽명
```

여기서 `k` 배열의 fx, fy, cx, cy 를 읽어 학습 데이터의 값과 대조한다.
현재 학습 데이터는 **fx = fy = 317.2, cx = 320, cy = 240 (640×480)** 이다.

**해상도가 640×640 → 640×480 으로 바뀌면 세로 화각이 달라진다.** 가로만 맞추면 안 된다.
Isaac Sim 쪽 변경을 기다리지 말고, **실제로 들어오는 영상에 블렌더 설정을 맞추는 편이 빠르다.**
`render_book_dataset.py --hfov <값>` 으로 재생성하면 된다.

## 3. 가장 중요한 남은 작업 — 도메인 갭 측정

**학습은 블렌더 렌더로 했고, 실제 추론은 Isaac Sim 렌더에서 한다.** 렌더러가 달라 성능이
떨어질 수 있는데, 아직 측정하지 못했다.

### 최소 성공 조건 — 이것만 되면 성공이다

> **랜덤화 없이 고정 조명·고정 배경으로 Isaac Sim 이미지 30장에 라벨을 붙여,
> 블렌더 학습 모델의 mAP 를 재고 blender-val 과 비교한 숫자 하나를 얻는다.**

30장이면 정밀한 값은 아니지만 **갭이 5pt 인지 30pt 인지는 구분된다.** 그 구분만으로 의사결정이 된다.
150~300장은 목표이지 조건이 아니다. **완벽한 버전을 노리다 아무것도 못 내는 것이 최악이다.**

### 순서 (이 순서를 지킬 것)

**0단계 — K 행렬 확인이 먼저다.** 화각이 어긋난 상태에서 갭을 재면 렌더러 차이인지 기하 차이인지
구분할 수 없는 숫자가 나온다. 우리는 이미 같은 실패를 두 번 했다. 2절 참조.

1. Isaac Sim 에서 손목 카메라로 책 이미지를 저장한다(최소 30장, 목표 150~300장).
   Replicator 어노테이터로 bbox·인스턴스 분할 라벨을 뽑는다. **랜덤화는 최소로.**
2. 블렌더로 학습한 모델을 두 검증셋에 돌려 mAP 를 비교한다. **conf·IoU 설정을 동일하게 할 것.**
   설정이 다르면 비교가 무의미하다.

### 흔한 실패 (미리 알고 갈 것)

| 증상 | 원인 |
| --- | --- |
| 라벨이 전부 비어 있음 | **책 prim 에 세만틱 라벨이 없다.** 가장 흔한 실패 |
| 배경까지 객체로 잡힘 | 배경 prim 에 세만틱이 붙어 있다 |
| 크기가 이상함 | 단위 불일치 (cm vs m) |
| 두 검증셋 수치가 비교 불가 | 해상도·conf·IoU 설정이 다름 |
| 어노테이터 이름 오류 | **버전마다 다르다. 설치된 5.1.0 예제에서 확인할 것** |

예상 소요: 최소 버전 2시간, 전체 반나절.

```bash
yolo val model=best.pt data=<블렌더 검증셋>/data.yaml
yolo val model=best.pt data=<Isaac 검증셋>/data.yaml
```

### 결과별 대응

| mAP 차이 | 대응 |
| --- | --- |
| 5pt 미만 | 갭 무시 가능. 그대로 진행 |
| 5~15pt | **증강 강화 후 재학습.** `train_yolo.py` 의 HSV·밝기·대비 범위를 넓힌다. 비용은 학습 1회 |
| 15pt 초과 | Isaac 이미지 **200~500장을 섞어 파인튜닝** |

**이 측정값 자체가 보고서의 핵심 지표다.** "도메인 갭을 정량화했다"는 것은 다른 팀이 갖기 어려운
근거다. 갭이 작다는 결과가 나와도 실패가 아니라 검증된 설계 결정이다.

## 4. 파지 대상 선택 규칙 (구현됨, 개선 필요)

로봇은 한 번에 한 권만 집는다. 그래서 **"가장 위에 있는 책"** 을 고르면 된다.

```
탐지된 인스턴스 중 → 깊이 중앙값이 가장 작은 것 선택 (= 카메라에 가장 가까움 = 최상단)
```

더미는 항상 위에서부터 푼다. 최상단은 가림이 가장 적고, 집을 때 다른 책을 건드릴 확률도 낮다.

### 이미 고쳤다 — bbox 를 마스크로 바꾸고 순위 분포를 쟀다

인계 직전에 두 가지를 수정해 다시 측정했다(겹침 450장 기준).

1. `median_depth()` 가 bbox 안에서 깊이를 재고 있었다 → **마스크 안에서 재도록 수정**
   (회전한 책의 bbox 는 절반이 배경·옆 책이라 중앙값이 오염된다)
2. "정답 최상단과 일치율" 하나만 보던 것을 **깊이 순위 분포**로 바꿨다

| 고른 책의 실제 깊이 순위 | 비율 |
| --- | --- |
| 1위 (최상단) | **76.0%** |
| 2위 | 4.2% |
| 3위 이하 | 0.9% |
| GT 와 IoU 0.5 매칭 실패 | 18.9% |
| **1~2위 안에 드는 비율** | **80.2%** |

마스크로 바꾼 효과는 74.0% → 76.0% 로 2pt 에 그쳤다. **원인 추정이 틀렸다.**

### 진짜 원인은 선택이 아니라 경계 품질이었다

매칭 실패 85건이 어느 정도 빗나갔는지 재봤다.

| 고른 예측과 가장 잘 맞는 GT 의 IoU | 건수 |
| --- | --- |
| 0.3~0.5 (거의 맞았으나 기준 미달) | 43 |
| 0.1~0.3 (책 두 권에 걸쳤거나 조각남) | 40 |
| **0.1 미만 (완전히 엉뚱한 곳)** | **2** |

**450장 중 완전히 다른 곳을 고른 경우는 2장(0.4%)뿐이다.** 즉 "어느 책을 집을지"는 거의 항상
맞히고 있고, 남은 문제는 **마스크 경계가 IoU 0.5 를 못 넘기는 것**이다.

이것은 선택 규칙이 아니라 탐지 품질의 문제이므로, **선택 로직을 더 손보는 것은 이득이 적다.**
5-2절의 관통 배치(두 책이 같은 자리 → 경계가 모호)가 이 40건의 상당 부분일 가능성이 높다.

### 그래도 남은 개선 여지

### 더 나은 선택 기준

깊이 중앙값 대신 **RANSAC 평면의 중심 깊이**를 쓰는 것을 권한다. `estimate_pose.py` 가 이미
평면을 구하고 있으므로, 이상치가 제거된 값이고 **선택한 대상과 자세를 추정한 대상이 같은 계산에서
나온다**는 일관성 이득이 있다. 퍼센타일(가장 가까운 10% 등)은 경계 픽셀에 민감하니 쓰지 말 것.

보조 조건 하나를 더 걸면 안전하다. **DB 치수로 기대 투영 면적을 계산**하고, 실제 마스크 면적이
그보다 현저히 작으면 가려진 것으로 보고 다음 후보로 넘긴다. 별도 학습 없이 가림을 추정하는 방법이다.

## 5. 성능 — 집단을 나눠 봐야 한다

### 전체 지표는 오해를 부른다

| 평가 집단 | Box mAP50 | Mask mAP50 | Recall |
| --- | --- | --- | --- |
| 전체 valid (345장, **87%가 단권 장면**) | 0.994 | 0.992 | 0.985 |
| **겹쳐 쌓인 장면만 (450장, 1,501 인스턴스)** | **0.957** | **0.934** | **0.895** |

**CP1 이 다루는 조건은 후자다.** 보고할 때 전체 수치만 쓰면 안 된다.

### 가림·크기 구간별 (겹침 **450장**, GT에 학습과 동일한 0.85 필터 적용)

| 가림 | 개수 | Recall | | 마스크 크기 | 개수 | Recall |
| --- | --- | --- | --- | --- | --- | --- |
| 0~10% | 1,189 | 78.5% | | ~2,000px | 92 | 82.6% |
| 10~30% | 285 | 70.9% | | 2,000~10,000 | 630 | 96.0% |
| 30~50% | 127 | 94.5% | | 10,000~40,000 | 757 | **65.3%** |
| 50%+ | 169 | 78.1% | | 40,000~ | 291 | 72.9% |

신뢰도를 0.05 로 낮추면 각 구간이 3pt 정도 오른다.

**주목할 것은 작은 객체가 아니라 큰 객체다.** 10,000~40,000px 구간이 65.3% 로 가장 낮다.
화면을 크게 차지하는 책 — 즉 **지금 집으려는 바로 그 책** 이 속하는 구간이다.
4절의 "매칭 실패 85건"과 같은 현상으로 보이며, 경계가 잘리거나 두 책에 걸친 경우다.
**개선한다면 여기가 우선이지 작은 객체가 아니다.**

### 측정할 때 반드시 맞출 것

**평가 GT 에 학습과 동일한 가림 필터(0.85)를 적용할 것.** 적용하지 않으면 학습에서 제외한 것을
"못 맞혔다"고 세어 성능이 왜곡된다. 실제로 필터 적용 전후가 이만큼 달랐다.

| 구간 | 필터 없음 | 필터 적용 |
| --- | --- | --- |
| 가림 50%+ | 62.0% (250개) | **78.1%** (169개) |
| 마스크 ~2,000px | 59.5% (158개) | **82.6%** (92개) |

```bash
python3 eval_occlusion.py dataset_multi --weights <best.pt> --max-occlusion 0.85
```

### 작은 객체가 약한 것은 사실이나, 파지에는 치명적이지 않다

집을 대상은 항상 가장 가까운(크게 보이는) 책이다. 작은 객체를 놓치는 것은 "지금 집을 대상"이
아니라 "멀리 있는 다른 책"을 놓치는 것이다.

**트레이 잔량 파악에는 쓰지 말 것.** RFID + DB 가 어떤 책이 몇 권 나왔는지 이미 알고 있다.
비전으로 개수를 세는 것은 아는 정보를 불확실한 방법으로 다시 구하는 것이다.

개선이 필요하다면 순서는 이렇다.
1. **관측 자세 표준화** — 트레이가 화면을 채우는 거리를 확정하고 그 대역으로 데이터 재생성
   (`--dist MIN MAX`). 로봇팔·AMR 담당과 합의 필요
2. `--imgsz 960` 으로 학습 (27.5분 → 60분, 추론 1.3ms → 3ms 수준)

### 재생성할 때 적용할 설정 (지금 바꾸지 말 것)

도메인 갭이 15pt 를 넘어 재생성하게 되면 아래를 **한 번에 함께** 반영할 것.

| 항목 | 현재 | 재생성 시 |
| --- | --- | --- |
| 겹침 장면 비율 | 이미지 10% (360/3,510) | **40~50%** |
| 관측 거리 대역 | `--fill 0.25 0.65` | 확정된 관측 자세의 거리 |
| 배치 관통 버그 | 남아 있음 | `arrange()` 에서 3D 바운딩박스 교차 검사 (5-2절) |

**인스턴스 기준으로는 이미 27% 가 겹침이다**(겹침 장면은 장당 약 3.3권). 이미지 기준 10% 보다
덜 치우쳐 있고, 현재 겹침 성능이 그럭저럭 나오는 이유이기도 하다. 그래도 배포 분포는
"트레이에 여러 권이 쌓인 상태"가 대부분이므로 올리는 것이 맞다.

**단권을 0으로 만들지는 말 것.** 서가에서 슬롯을 확인하는 상황이 CP3 에 있다.
겹침 장면은 단권 패턴을 포함하지만(가려지지 않은 책 하나하나가 단권과 같다) 역은 성립하지 않는다.
그래서 겹침을 늘리는 쪽이 비대칭적으로 이득이다.

## 5-2. 알려진 결함 — 책이 같은 자리에 겹쳐 배치되는 경우

겹침 장면 450장 중 104장에서 **서로 다른 책의 bbox 가 완전히 동일**했다.
쌓기 로직에서 두 책이 관통한 것이다. 둘의 깊이가 같으니 "가려지지 않았다" 판정을 둘 다 통과해
각각 온전한 마스크를 갖는다.

```
index=1 book_softcover_01_cover01  bbox=[0,0,416,325]
index=3 book_softcover_01_cover04  bbox=[0,0,416,325]   ← 동일
```

**조치 상태**
- 변환 단계에서 **중복 제거를 넣었다** (`export_yolo.py`, 같은 영역이면 하나만 남기고 경고)
- **배치 로직은 고치지 않았다.** `render_multi_book.py` 의 `arrange()` 에서 겹침 검사가
  같은 높이(`z` 차이 0.01m 이내)일 때만 동작한다. 쌓기 경로는 높이가 다르다는 이유로 통과한다.
  **고치려면 배치 후 실제 3D 바운딩박스 교차를 검사해야 한다**

현재 학습에 쓴 데이터에는 이 중복이 포함되어 있었다(전체 라벨의 14%, 104/450 파일, 252줄).

### 재학습해서 비교했다 — 영향이 없었다

**분할·이미지를 그대로 두고 라벨의 중복 줄만 제거해** 동일 설정으로 다시 학습했다(대조 실험).
평가셋은 겹침 450장으로 고정했다.

| 지표 | 중복 포함 (현재 `best.pt`) | 중복 제거 재학습 |
| --- | --- | --- |
| Box mAP50 | 0.9569 | 0.9552 |
| Box mAP50-95 | 0.8978 | 0.8908 |
| Box Recall | 0.8947 | **0.9041** |
| Mask mAP50 | 0.9342 | 0.9272 |
| Mask mAP50-95 | 0.8460 | 0.8334 |

**차이가 모두 1pt 미만이고 부호도 엇갈린다. 라벨 중복 14% 는 성능에 유의미한 영향이 없었다.**

구간별로는 큰 객체 쪽이 조금 나아졌다(10k~40k 65.3% → 69.6%, 40k~ 72.9% → 75.6%).
다만 이 역시 오차 범위로 볼 수 있는 크기다.

> 단서: 이 평가셋 450장은 두 모델 모두 학습에 포함된 이미지다. 절대 성능이 아니라
> **두 모델의 차이**를 보기 위한 비교이고, 그 목적에는 유효하다.

**따라서 중복 때문에 재학습할 필요는 없다.** `runs/segment/runs/book_dedup/` 에 재학습 모델을
남겨 두었으니 필요하면 쓰면 되고, 기본은 기존 `best.pt` 를 그대로 쓰면 된다.
**변환기의 중복 제거는 그대로 두었다** — 앞으로 만들 데이터에는 이 문제가 없어야 하기 때문이다.

## 5-3. 자세 추정 — 현재 성능과 개선 방향

`estimate_pose.py` 는 학습 없이 마스크 + 깊이로 파지 자세를 계산한다.

| 항목 | 중앙값 | 90% | 실패율(30도 초과) |
| --- | --- | --- | --- |
| 법선(접근 방향) | 1.19° | 8.27° | 5.3% |
| 장축(그리퍼 회전) | 0.49° | 30.06° | 10.6% |
| 중심 위치 | 5.23mm | 16.68mm | 10mm 이내 78.8% |

방식: 마스크 3px 침식 → RANSAC 평면 적합 → 최소외접사각형으로 장축.
**두께는 추정하지 않는다. RFID 가 신원을 주므로 DB 에서 조회한다.**

### 남은 문제 — 이봉분포

중앙값 1.19° 인데 실패율 5.3% 다. **대부분 훌륭하고 가끔 파국적이다.** RANSAC 이 윗면 대신
옆면을 고르면 법선이 90도 어긋난다.

**추가할 판별 조건 (권장 순서)**

1. **시선 정렬** — 한 줄이고 가장 효과적이다. 손목 카메라는 위에서 내려다보므로 윗면 법선은
   시선을 향하고 옆면 법선은 시선과 거의 수직이다.
   ```python
   if abs(dot(normal, view_direction)) < 0.5:   # 시선에서 60도 이상 벗어남
       reject()
   ```
2. **DB 치수와 대조** — 적합된 평면의 2D 범위를 재서 한 변이 5cm 미만이면 옆면으로 판정해 기각
   (책 두께는 2~4cm, 윗면은 가로·세로 15~22cm)
3. **inlier 비율** — 마스크 점군의 60% 미만이 평면에 들면 기각 (윗면이라면 대부분이 한 평면에 든다)

**연속 점수를 만들어 임계값을 튜닝하지 말 것.** 실패 사례가 553장 중 29건뿐이라
그 숫자로 임계값을 맞추면 과적합된다. 위 세 개는 통계가 아니라 **기하학에서 임계값이 나오므로**
튜닝이 필요 없다. 세 게이트를 적용한 뒤 **(기권율, 잔여 실패율) 한 쌍만 측정하고 끝낼 것.**

### 더 중요한 것 — 기권 메커니즘

**실패율을 5.3%에서 3%로 낮추는 것보다, 실패를 미리 알아채는 것이 로봇에게 훨씬 가치 있다.**
법선이 90도 틀린 채로 흡착하면 파지 실패이거나 책 손상이다.

```
세 게이트 중 하나라도 걸림  →  "추정 실패" 반환
                            →  FSM 이 관측 자세를 15~20도 옆으로 옮겨 재촬영
                            →  2회 기권 시 해당 책 건너뛰고 다음 후보
                            →  후보 소진 시 오퍼레이터 호출
```

**"자세를 옮겨서" 재촬영해야 한다.** 같은 자세에서 다시 찍으면 같은 점군이 나오고 같은 평면이
나온다. 무한 루프다. 각도를 바꾸면 옆면이 시야에서 줄고 윗면 비율이 올라가므로,
원인이 시선각이었다면 실제로 해결된다. **이 조건을 FSM 담당자와 합의해 둘 것.**

**틀린 답보다 "모르겠다"가 낫다.** 재관측 비용은 몇 초지만 잘못된 파지는 훼손이다.
보고서에도 "실패율 5.3%" 보다 **"기권 4.8%, 기권하지 않은 경우의 실패율 0.5%"** 가 나은 서술이고
실제로 더 나은 시스템이다.

## 8. 블렌더 5.x 함정 (기억이나 옛 문서에 의존하면 틀린다)

| 항목 | 5.x에서의 실제 |
| --- | --- |
| `scene.node_tree` | 제거됨 → `scene.compositing_node_group` |
| `Composite` 노드 | 제거됨 → Group Output |
| File Output 노드 | `base_path`/`file_slots` → `directory`/`file_name`/`file_output_items`, **멀티레이어 EXR만 지원** |
| `CompositorNodeMath` | 제거됨 → `ShaderNodeMath` |
| EEVEE 엔진 식별자 | 버전마다 다름 → 목록에서 골라 쓸 것 |
| **오브젝트 인덱스 패스** | **EEVEE 미지원** (Cycles 전용) |

마지막 항목 때문에 인스턴스 마스크를 **책마다 깊이를 따로 렌더해 장면 깊이와 비교하는 방식**으로
구현했다. 결과적으로 가림 비율을 추정이 아니라 정확한 값으로 얻게 되어 더 나은 결과가 되었다.

### USD 내보내기 함정 (아이작심에서 UV 가 깨진 원인, 2026-09-16 밤 실측)

| 원인 | 증상 | 처리 |
| --- | --- | --- |
| `rename_uvmaps=True` (기본값) | UV 가 두 장인 책에서 **활성 UV 하나만 `st` 로 개명**되는데 셰이더 varname 도 `st` 로 적혀, 표지가 엉뚱한 UV 로 샘플링된다 | `rename_uvmaps=False` |
| UsdPreviewSurface 표현력 | 마스크로 합성한 노드 그래프는 USD 로 못 나간다. 텍스처 한 장만 나가고 나머지가 사라진다 | **베이크해서 한 장으로** |
| UDIM | `<UDIM>` 토큰이 그대로 나가 아이작심이 타일을 못 찾는다 | 베이크가 해결한다 |
| `export_subdivision='BEST_MATCH'` (기본값) | SUBSURF 가 걸린 책이 저폴리 케이지로 나간다 (812 → 3216 폴리곤 차이) | `TESSELLATE` |
| 베이크용 UV 를 만들 때 `active_render` 를 옮김 | UVMap 노드가 없는 재질이 **빈 UV 로 원본을 샘플링**해 뒷면이 구워진다 | 베이크가 끝난 뒤에 옮긴다 |

`export_usd_assets.py` 가 이 다섯 가지를 모두 처리한다. 내보낸 뒤에는 **USD 를 블렌더로 다시
불러와 렌더해 원본과 나란히 비교**했다. 이 왕복 확인 없이는 발견하지 못했을 문제들이다.
