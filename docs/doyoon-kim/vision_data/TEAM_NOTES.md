## 1. 무엇을 만들고 있나

블렌더에서 책을 여러 각도·조명·배경으로 자동 촬영해 **라벨이 붙은 학습 이미지**를 만든다.

**핵심: 사람이 바운딩 박스를 그리지 않는다.**
블렌더는 책의 3D 형상과 카메라 위치를 이미 알고 있으므로 라벨을 수식으로 계산한다.
정확도는 블렌더 자체 투영 함수와 대조해 **오차 0.00px**로 검증했다.
학습 과정은 일반적인 지도학습 그대로이며, 라벨의 출처만 "사람의 클릭"에서 "기하 계산"으로 바뀐 것이다.

한 장마다 나오는 것:

| 파일 | 내용 |
| --- | --- |
| `images/000000.png` | 컬러 이미지 |
| `depth/000000.png` | 깊이 맵. **16비트 PNG, 밀리미터 단위. 65535 = 배경** (RealSense와 같은 규약) |
| `mask/000000.png` | 책만 남긴 알파 마스크. 세그멘테이션 학습과 정확한 bbox 계산에 사용 |
| `labels/000000.json` | bbox, 6D 자세, 카메라 내부 파라미터, 랜덤화 기록 |

## 2. 확정된 규약 (변경 시 전원 합의 필요)

### 2.1 카메라

| 항목 | 값 | 근거 |
| --- | --- | --- |
| 가로 화각 | **90.5°** | Isaac Sim USD의 손목 카메라(`Camera_OmniVision_OV9782_Color`) 실측값 |
| 해상도 | **640 × 480** | 브리프 10절 권고, RealSense D435 기본 해상도 |
| 블렌더 렌즈 환산 | 17.84 mm (센서 36 mm 기준) | `--hfov 90.5` 로 자동 계산 |

> **팀원 1(Isaac Sim 담당)에게 요청**
> USD의 `camera_graph > RenderProduct` 노드가 현재 **640 × 640**이다. **640 × 480**으로 변경 필요.
> 화각은 그대로 두면 된다(90.5°). 학습 데이터를 이 값에 맞춰 생성했다.

화각이 다르면 같은 책도 원근이 다르게 찍혀 인식 성능이 떨어진다. 해상도보다 화각 일치가 더 중요하다.

### 2.2 좌표계

- 자세 라벨 `T_cam_obj`는 **OpenCV 규약**: +Z 앞, +X 오른쪽, +Y 아래
- 블렌더 카메라(-Z 앞, +Y 위)에서 X축 180° 회전으로 변환한 값이다
- 단위는 미터

### 2.3 라벨 JSON 필드

```jsonc
{
  "frame": 0,
  "image": "images/000000.png",
  "depth": "depth/000000.png",      // uint16 mm, 65535 = 배경
  "mask":  "mask/000000.png",        // 알파 채널이 책
  "book":  "book_encyclopedia_set_01_book01",
  "blend": "book_encyclopedia_set_01_2k.blend",

  "K": {"fx": 317.2, "fy": 317.2, "cx": 320.0, "cy": 240.0, "width": 640, "height": 480},

  "T_cam_obj": [[...4x4...]],        // OpenCV 규약, 카메라 기준 책의 자세
  "quat_wxyz": [w, x, y, z],
  "translation": [x, y, z],          // 카메라에서 책 원점까지 (m)
  "distance_m": 0.52,

  "obj_dims": [0.126, 0.037, 0.149], // 책 크기 (m)
  "bbox_local": [[...8x3...]],       // 로컬 3D 박스 8점
  "corners_2d": [[u, v], ...],       // 위 8점의 2D 투영
  "bbox_2d": [x0, y0, x1, y1],       // 마스크 기준 정확한 값
  "bbox_2d_projected": [...],        // 3D 박스 투영값 (비교용, 평균 1.03배 큼)
  "bbox_source": "mask",
  "visibility": {"corners_in_view": 8, "ratio": 1.0},

  "randomization": { "camera": {...}, "book": {...}, "lights": [...],
                     "world": {...}, "materials": {...} }
}
```

## 4. 실행 방법

### 4.1 데이터 생성 (한 권)

```bash
cd ~/ws_cobot_pjt/book_dataset
blender -b <에셋>.blend -P render_book_dataset.py -- \
    --out /tmp/test --views 40 --res 640 480 --hfov 90.5 \
    --book <오브젝트 이름> --isolate
```

자주 쓰는 옵션:

| 옵션 | 용도 |
| --- | --- |
| `--list-objects` | 에셋에 든 메쉬와 크기만 출력 |
| `--isolate` | 세트 에셋에서 대상 한 권만 렌더 |
| `--join <정규식>` | 표지·책장처럼 나뉜 메쉬를 한 권으로 합침 |
| `--scale-to 0.22` | 단위가 제각각인 에셋을 실측 크기로 정규화 |
| `--hfov 90.5` | 가로 화각 지정 (Isaac Sim과 일치시킬 것) |
| `--export-usd <경로>` | 책을 USD로 내보내기 |
| `--only-mask` | 같은 시드로 마스크만 다시 생성 |
| `--dry-run` | 렌더 없이 라벨만 (좌표 확인용) |

### 4.2 여러 에셋 일괄 생성

```bash
python3 build_datasets.py --config assets_config.json --hfov 90.5 --res 640 480
```

`assets_config.json`에 에셋별 설정(합치기·크기·권 수)이 들어 있다.

### 4.3 검증

```bash
python3 check_labels.py dataset/<에셋>/<책> --limit 10
```

이미지 위에 bbox·3D 박스를 그려 `preview/`에 저장하고, 깊이 값이 라벨 거리와 맞는지 확인한다.

### 4.4 학습용 형식 변환 (필요할 때만)

```bash
python3 export_roboflow.py dataset --out yolo_dataset --format yolo
```

YOLO(`images` + `labels/*.txt` + `data.yaml`)와 COCO를 만든다. **같은 책이 train과 valid에 섞이지 않도록 책 단위로 분할**한다.

### 4.5 CC0 에셋 추가 다운로드

```bash
python3 download_polyhaven.py <에셋ID> --res 2k
```

## 5. 학습 방향 (제안, 미확정)

- **모델: YOLO11-seg, 단일 클래스 `book`** — 마스크가 있으므로 세그멘테이션이 유리하다
- **6D 자세는 학습하지 않는다.** 마스크 + 깊이로 점군을 만들고 주성분 분석(PCA)으로 파지 자세를 계산한다.
  우리가 가진 6D 라벨을 정답으로 삼아 이 계산의 오차(mm, 도)를 측정할 수 있다 → 기술 노트 지표로 사용
- **도메인 차이 주의**: 학습은 블렌더 렌더, 추론은 Isaac Sim 렌더다. 화각을 맞췄어도 질감·조명 차이가 남는다.
  Isaac Sim에서 검증용 이미지를 소량 뽑아 실제 성능을 측정할 것
- Ultralytics YOLO는 AGPL 라이선스다. 과제에는 문제없으나 인지하고 쓸 것

**bbox 정확도** — 마스크 기준으로 교체 완료. 3D 박스 투영 대비 면적비 중앙값 1.027배,
95 퍼센타일 1.254배. 2배를 넘는 9장(1.07%)은 책이 화면 밖으로 잘리면서 투영 박스만 커진 경우다.
마스크 기준으로 바꾼 이유가 이 구간에서 드러난다.

**자세 추정 (`estimate_pose.py`, 553장 측정 / 287장은 잘림으로 제외)**

| 항목 | 중앙값 | 90% | 비고 |
| --- | --- | --- | --- |
| 법선(접근 방향) 오차 | 3.37° | 9.36° | 30° 초과 실패 2.0% |
| 장축(그리퍼 회전) 오차 | 1.95° | 13.33° | 30° 초과 실패 6.0% |
| 중심 위치 오차 | 5.13mm | 13.72mm | 10mm 이내 80.8% |

> 이전 측정(책이 작게 찍힌 데이터)보다 중심 오차가 4.13mm → 5.13mm로 커졌다.
> 책을 크게 찍으면서 화면 밖으로 잘리는 프레임이 늘었기 때문이다.
> 잘린 점군은 축 범위가 실제보다 짧게 잡혀 중심이 밀린다.
> 탐지 학습에는 잘린 프레임이 오히려 도움이 되므로 그대로 두고, 자세 추정에서만 걸러 쓴다.

**알려진 문제**: 낮은 각도 프레임 일부에 바닥 끝 경계선이 보인다. 바닥 기본값을 50m로 올렸으므로
다음 생성부터는 사라진다. 현재 840장은 그대로 사용 가능하다.

## 6.8 여러 권 장면 (CP1용) — 2026-09-16 추가

무인반납기 트레이에는 책이 여러 권 쌓여 나온다. 한 권짜리 데이터만으로는
**"겹친 책 중 한 권만 분리해 잡는"** CP1 상황을 검증할 수 없어 따로 만든다.

```bash
blender -b <에셋>.blend -P render_multi_book.py -- \
    --out dataset_multi --views 40 --books 2 5 --hfov 90.5 --res 640 480
python3 add_instance_bbox.py dataset_multi
```

| 옵션 | 기본값 | 뜻 |
| --- | --- | --- |
| `--books MIN MAX` | 2 5 | 한 장면의 권 수 |
| `--flat-prob` | 0.85 | 책을 눕힐 확률. 트레이 상황이라 눕힘 위주 |
| `--stack-prob` | 0.45 | 이미 놓인 책 위에 쌓을 확률 |
| `--elev` | 25~85° | 트레이를 내려다보는 각도 |

**인스턴스별로 얻는 것**: bbox, 보이는 픽셀 수, **가림 비율(occlusion)**, 6D 자세, 눕힘·쌓임 여부.

### 인스턴스 마스크를 만드는 방법 (중요)

오브젝트 인덱스 패스가 있으면 한 번의 렌더로 끝나지만 **EEVEE 는 이 패스를 지원하지 않는다**
(Cycles 전용). 그래서 기본 경로는 다음과 같다.

1. 장면 전체 깊이를 렌더한다
2. 책마다 그 책만 남기고 깊이를 다시 렌더한다 (`inst/000000_01.png`)
3. 두 깊이가 같은 화소만 "실제로 보이는 부분"이다. 장면 깊이가 더 가까우면 다른 책이 가린 것이다

이 방법은 가림 비율을 추정이 아니라 **정확한 값**으로 준다. 책마다 렌더가 한 번씩 더 들지만
샘플 1로 돌려 부담이 적다.

## 6.10 아이작심용 USD 내보내기 (2026-09-16 밤)

**증상**: GPU PC 가 만든 usdc 를 아이작심에서 열면 일부는 정상인데 대부분 UV 가 뒤집히거나 깨졌다.

**원인은 다섯 가지였고 전부 블렌더 5.2 에서 실측 확인했다.**

| # | 원인 | 확인 방법 |
| --- | --- | --- |
| 1 | `rename_uvmaps=True`(기본값)가 UV 2장 에셋에서 varname 을 어긋나게 쓴다 | `.usda` 덤프 비교 — rename True → `varname="st"`, False → `varname="cover"` |
| 2 | UsdPreviewSurface 가 마스크 합성 노드 그래프를 표현하지 못한다 | 텍스처 7장 중 1장만 나감 |
| 3 | UDIM `<UDIM>` 토큰이 그대로 나간다 (FBX 책, 타일 1001~1003) | 이미지 `source == "TILED"` |
| 4 | `export_subdivision='BEST_MATCH'`(기본값)가 저폴리 케이지를 내보낸다 | 812 → 3216 폴리곤 |
| 5 | 베이크용 UV 생성 시 `active_render` 를 먼저 옮기면 **뒷면이 구워진다** | USD 왕복 렌더 |

**5번은 우리가 만든 버그였고, 수치로는 전혀 드러나지 않았다.**
USD 를 블렌더로 다시 불러와 원본과 나란히 렌더해서야 발견했다.
**화각 사고 두 번에 이어 세 번째로, 육안 확인이 유일한 검출 수단이었던 사례다.**

**처리**: `export_usd_assets.py` 가 다섯 가지를 모두 처리한다.
노드 그래프 재질을 텍스처 한 장으로 굽고(2K), UV 를 `st` 한 장으로 정리해 내보낸다.

```bash
blender -b <에셋>.blend -P export_usd_assets.py -- --out dataset/usd_v2
blender -b <에셋>.blend -P export_usd_assets.py -- --out /tmp/x --format usda   # 검증용 텍스트
```

**산출물**: `dataset/usd_v2/` 111개 (백과사전 20, 장식용 87, FBX 3, 오래된 책 1), 311MB.
GPU PC `~/book_dataset/usd_v2/` 에도 동기화했다. 기존 `dataset/usd/` 는 폐기 대상이다.

**아이작심 쪽 주의**: Surface Gripper 로 잡으려면 책에 Articulation Root 가 없어야 한다.
순수 Rigid Body + 충돌체로 설정할 것.

## 6.11 중복 라벨 대조 실험 (2026-09-16 밤)

겹침 데이터를 YOLO 로 변환할 때 **같은 영역을 가리키는 라벨이 중복 생성**되고 있었다
(450장 중 104장, 252줄, 전체의 14%). 두 책이 같은 자리에 관통 배치된 경우다.

변환기에 중복 제거를 넣은 뒤, **분할·이미지를 고정하고 라벨만 중복 제거해** 재학습해서 비교했다.

| 지표 (겹침 450장) | 중복 포함 | 중복 제거 |
| --- | --- | --- |
| Box mAP50 | 0.9569 | 0.9552 |
| Box Recall | 0.8947 | 0.9041 |
| Mask mAP50 | 0.9342 | 0.9272 |

**전부 1pt 미만이고 부호가 엇갈린다 → 중복 14% 는 성능에 유의미한 영향이 없었다.**
재학습 모델은 `runs/segment/runs/book_dedup/` 에 남겼고, 기본은 기존 `best.pt` 를 쓴다.

어느 쪽이 나오든 쓸 수 있는 실험이었다. "데이터 결함을 발견했고, 영향을 측정했고,
측정 결과에 따라 재학습하지 않기로 했다"가 보고 가능한 서술이다.

## 8. 팀원 AI 에이전트에게

이 파이프라인을 건드리거나 이어서 작업할 때 지켜야 할 것:

1. **좌표 규약을 바꾸지 말 것.** 라벨은 OpenCV 규약(+Z 앞, +Y 아래)이고, 블렌더에서 변환해 넣는다.
2. **깊이 단위는 밀리미터 uint16, 65535는 배경.** 미터 실수로 바꾸면 기존 데이터와 섞인다.
3. **화각 90.5°, 해상도 640×480을 유지할 것.** 바꾸려면 Isaac Sim 쪽도 같이 바꿔야 한다.
4. **블렌더 API를 기억으로 쓰지 말 것.** 5.x에서 다음이 모두 바뀌었다.
   - `scene.node_tree` → `scene.compositing_node_group`
   - `Composite` 노드 삭제 → Group Output
   - File Output: `base_path`/`file_slots` → `directory`/`file_name`/`file_output_items`, 멀티레이어 EXR만 지원
   - `CompositorNodeMath` → `ShaderNodeMath`
   - EEVEE 엔진 식별자가 버전마다 다름 → 목록에서 골라 쓸 것
5. **순수 계산은 `pose_math.py`에 두고 블렌더 없이 테스트할 것.** 현재 테스트 20개가 통과 상태다.
   ```bash
   python3 -m pytest tests -q
   ```
6. 새 에셋을 넣을 때는 `--list-objects`로 구조부터 확인하고, 크기·분리 여부·텍스처 유무를 점검할 것.
